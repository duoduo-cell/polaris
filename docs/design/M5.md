# M5 设计：记忆（自己实现）

2026-10-11 实现（比排期 10-16 提前）。目标：北极星记得你说过的事，记忆**能看、能查历史、能删**，每条带"什么时候成立、从哪句话来"，新旧矛盾有记录、该问的时候问你。对标 Muse（记忆文件能看能改能删）和 Dots（记忆看不到单条），见 `PLAN.md` 0.0 第 3 条。

## 组成

| 部分 | 文件 | 做什么 |
|---|---|---|
| 表 | `memory_facts`、`memory_events`、`memory_suppressions`（迁移 `e7ebb3844407`） | 事实是**双时间线**：`valid_from / valid_to` 是这件事在现实里什么时候成立（"12 月起每周 5 天"），`recorded_at / superseded_at` 是北极星什么时候记下、什么时候被新说法取代。旧版本不删。每个更新决定记一条事件，带原话和理由 |
| 属性表 | `memory/schema.py` | 18 个属性：单值（每周能去几天）/ 多值（会的技术）/ 按公司分槽（投递、面试进度）/ 会往前走（面试进度：一面 → 二面不算矛盾）。值的归一（公司按大厂名单、城市去"市"、数字只留数字） |
| 抽取 | `memory/extract.py` | 模型只回答"这句话里关于你的事实是什么、你亲口说的还是推断的、是不是在改口、从哪天起成立"（提示词 v2） |
| 更新 | `memory/update.py` | **决定全部由规则做**：add / noop / update / schedule / invalidate / pending / ask / confirm / reject / suppressed / forget，见文件开头的表 |
| 工具 | `tools/memory.py` | `memory_card`（今天或某天成立的事实 + 待确认）、`memory_history`（某属性的全部版本和原话）、`memory_known_at`（某天北极星记着什么）、`memory_forget`（写操作，不经 MCP 开放） |
| 评测 | `eval/memory_eval.py`、`eval/gold/memory_v1.json`、`memory_holdout_v1.json` | 单独的 `polaris_memeval` 库，按时间重放虚构求职者的对话，比每句话的记忆操作，再按 LongMemEval 的五种能力提问 |

## 几个设计决定

- **模型抽、规则定。** 同一句话两次跑，模型抽出的候选可能不同，但"怎么改记忆"不交给模型：新增、更新、作废、追问都由属性表和规则决定，可以写单元测试（`tests/test_memory.py`，20 个用例），也能在评测里逐条对账。参考 Mem0 的"新增 / 更新 / 删除 / 不变"四种操作，但 Mem0 让模型选操作，北极星不让。
- **推断的先待确认，否认过的不再提**（借 WeKnora 的两点）。"字节约了我一面"能推出"投过字节"，但先进待确认、问一句；你说"对，投的是 Agent 开发实习"就生效并补全说法；你说"没投"就作废，并按公司记一条抑制——下次换个说法推断"在面腾讯"也不会再提。否认某公司时，同公司牵连的推断（面试进度）一并作废。
- **矛盾先问，不直接覆盖。** 单值的槽已有别的值、你最近才说过、也没说要改，就不覆盖，新说法进待确认，问你以哪个为准；你明确改口、旧的是推断、或旧的超过 30 天没再提，才直接更新。进度类属性（面试一面 → 二面）本来就会往前走，直接更新。
- **将来的安排单独记。** "12 月起每周能去 5 天"：现在的 3 天到 11 月 30 日为止，新的从 12 月 1 日起，两条都有效，`memory_card(on=12 月某天)` 自然答 5 天。
- **能看、能查历史、能删。** 卡片每条带编号 M-；`memory_history` 给出每个版本、原话、什么时候被取代；`memory_forget` 作废并记抑制，旧记录留档。写操作不经 MCP 开放，M6 接人工审批。

## 结果

见 `../../eval/reports/M5.md`。评测按时间分三份，和同岗识别一样防止对着看过的题调规则：每改一轮规则，上一份就变成开发集，再写一份新的只评不调。

| | 开发集（4 人 28 句 23 问） | 留出集（第一版改完才写，4 人 16 句 16 问） | 测试集 v2（第三版改完才写，3 人 16 句 13 问） |
|---|---|---|---|
| 第一版 | 操作 F1 0.90，问答 20/23（2 题是评分漏认"你没跟我说过"） | — | — |
| 第二版 | 0.93，问答 23/23 | 0.92，整句全对 12/16，问答 16/16 | — |
| 第三版 | 0.97，整句全对 25/28 | 0.95，14/16 | **0.97（精确率 0.93、召回率 1.00），整句全对 14/16，问答 13/13** |

- 第一版 → 第二版（据开发集）：进度类属性不排到将来；否认某公司时牵连的推断一并作废并按公司抑制；提示词说清"研二"这类算亲口说的。
- 第二版 → 第三版（据留出集和实测）：**"该问没问"**——用户换了个数（"每周大概能去 4 天"）但没说要改，模型把它标成改口，规则直接覆盖了。
  改成模型判断之外，再由代码核对这句话里有没有明确的改口词（改、现在、其实、还是、说错……）；问"以哪个为准"时用户重申原来的说法，待确认的新说法作废。
  测试集 v2 上追问 2/2、确认 2/2、作废 1/1 都对了。
- 测试集 v2 上剩下的两处：同样的推断在等确认时又推断了一次（已改：直接算已知，改在测试集跑完之后）；"大四"推断成 2027 年毕业进了待确认（合理，是标准答案没写到）。

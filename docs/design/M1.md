# M1 设计：项目骨架

2026-10-10 用户确认，同日实现。目标：一条命令起服务、合成数据能入库、每次模型调用有记录。


## 数据表

M1 只建 M1 到 M3 用得到的表，后面的到对应模块用迁移加。

| 表 | 作用 | 关键字段 |
|---|---|---|
| raw_items | 采集器的统一输出 | source、tier（A/B）、kind、url、query、raw_text、content_hash（同源同哈希只存一次）、fetched_at |
| postings | 一条原文抽出的岗位（M2） | 岗位字段、raw_item_id、job_id（M3 归并后）、llm_call_id、prompt_version、embedding |
| jobs | 多来源合并后的岗位（M3） | 岗位字段、field_sources（每个字段取自哪条 posting）、first_seen_at、last_seen_at、status、is_baseline |
| companies | 公司 | name、aliases、is_big、ats、ats_board、discovered_from |
| llm_calls | 每次模型调用 | purpose、prompt_version、model、request、response、parsed_ok、error、attempt、四种 token、latency_ms、cost_usd、cache_key、cache_hit |
| runs | 每次运行 | kind、params、status、stats（指标）、git_commit |

岗位字段按 PRODUCT 第 5 节和 PLAN 第 4.2 节：公司、岗位名、方向、JD 正文、要求要点、城市、薪资（原文和数字）、类型、能否转正、发布日期、截止日、到岗时间、实习时长、每周天数。向量列 1024 维，带 HNSW 索引。

## 模型调用封装

- `chat`、`extract`（结构化抽取，返回校验过的对象）、`embed` 三个入口，全部记账。
- 按角色选模型：chat、extract、judge、brief，不单独配就用 `LLM_MODEL`。
- 结构化输出：先试 `json_schema`，服务不支持就换 `json_object`；本地按 Pydantic 校验，不合格把错误发回模型重试，最多两次。
- 429、5xx、超时、连不上：自己重试，等待时间逐次拉长，每次失败都记一条。
- 缓存：同样的模型和输入直接返回上次合格的回答，评测时打开。
- key 只在内存里，不进记录和日志。

## 接口

| 接口 | 用途 |
|---|---|
| `GET /health` | 数据库和模型配置，只显示模型名 |
| `GET /api/llm-calls`、`/{id}` | 调用记录列表和详情（含完整输入输出，可回放） |
| `GET /api/runs`、`/{id}` | 运行记录和指标 |
| `GET /api/raw-items`、`/{id}` | 原始条目 |
| `POST /api/ingest/raw-items` | 批量入库，Bearer 口令（`INGEST_TOKEN`），本机 B 档采集器和手动粘贴都走它 |

## 合成数据

事实由代码按固定种子定好，模型只负责写成招聘文本；写完用代码核对：给的事实短语必须原样出现，没给的信息不许出现。所以标准答案在生成时就确定了。60 条：普通 30、英文 4、冷门 10（标题不含方向关键词）、无关反例 6、转载重复 10（和原版有一个字段矛盾）。全部虚构公司，网址用 example.com。

## 实现时的调整

| 计划 | 实际 | 原因 |
|---|---|---|
| 用 respx 模拟网络请求 | 用 httpx2 自带的 MockTransport，封装支持传入网络客户端 | OpenAI SDK 3.x 底层换成了 httpx2，respx 拦不住 |
| 结构化输出每次自动探测 | 加了 `LLM_JSON_MODE`，可直接指定 json_object | 开发用的 DeepSeek 不支持 json_schema，每个进程都白试一次要多花 2 秒 |
| 运行记录记 git 版本 | 有未提交改动时带 `-dirty` | 让每个数字都能如实对应到代码版本 |
| alembic.ini 里写中文注释 | 改成英文 | 中文 Windows 上 Alembic 按 GBK 读这个文件，中文注释会读挂 |
| ruff 默认规则 | 指定 E、F、I、B、UP 五组，行宽 120 | ruff 0.17 默认规则很多，风格类的意义不大 |

## 留给后面模块的

- M2：DeepSeek 默认带思考，合成数据那次输出 token 里三分之二是思考。批量抽取时试试关掉思考，对比准确率和成本。
- M2：抽取评测时，城市、薪资等字段要先归一化（英文城市名、空格）再比较。
- M3：换到 Token Factory 的 Qwen3-Embedding-8B 时，确认它支持 `dimensions=1024`，否则截断后重新归一化；`embed_model` 列用来区分新旧向量，换模型要重算。

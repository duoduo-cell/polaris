# M3 设计：采集和抽取

2026-10-11 实现（比排期 10-13 提前）。目标：把小红书、Boss、大厂官网的真实内容采进来，抽成结构化的岗位和笔记，用人工写的标准答案量出抽取准确率，再在真实数据上跑工具调用套件。

## 几个设计决定

- **采到一条写一条。** 小红书一次调用几十秒，中途断了不丢已经采到的；入库按来源加内容指纹去重，重复采不会重复写。
- **每轮有调用上限，单个查询词也有上限**，免得第一个词把一轮的预算用光；碰到限流或登录过期立刻停下这一轮，不硬冲。
- **只看大厂在两处生效**：Boss 搜索时按公司规模筛，拿到列表后再按名单过滤，名单外的不打开详情（省调用、也少留别人的数据）；小红书按标题是否提到大厂决定纵向挖不挖。
- **B 档内容不出本机**：小红书和 Boss 的原文、笔记的标准答案、查过笔记的评测录像和回答原文都在 `data/`（不进仓库）；仓库里的报告只放汇总数字。
- **提示词改动要在留出集上验证。** 笔记抽取 v1 的错例（把写字楼"阿里双子塔"当成阿里、把"bat"展开成三家公司、城市里带括号说明）用来改出 v2，所以开发集上 v2 的分数偏高；留出集是改完之后才采、才标的。
- **评分的归一规则写死在代码里**，不在评测时临时判断，避免"看着差不多就算对"。

## 结果

见 `../../eval/reports/M3.md`。要点：

- 真实岗位 50 条抽取微平均 F1 0.99，合成岗位 60 条 0.99。官网原文结构清楚，这部分偏容易。
- 小红书笔记开发集 24 条：v1 0.96（多填 3 处），v2 1.00（据开发集改的，偏高）；留出集见报告。
- 工具调用套件 real-v1：14 题 pass^3 14/14，42 次全部成功，141 次工具调用参数一次合格率 100%，注入的 6 次故障全部恢复，完整回放 14/14 一致。
  **这一版仍然偏简单**：M2 时预计换真实数据后分数会下来，实际没有。能拉开差距的题（多跳对比、跨来源冲突、按时间筛、推荐类开放题）放进 Polaris-Bench。

# 求职结果、来源与跟进：本轮目标和整体框架

2026-10-11。用户已确认先记录方案，再整体修改、测试并加速。本文记录产品目标、实施范围和验收；技术主文档仍为 `../TECH.md`。

## 目标与边界

让「采集 → 检索 → 推荐 → 核实来源 → 保存决定 → 跟进」真正连起来。核心是每天用得上的求职工具，以及能核实的检索、记忆和冲突处理能力，见 `../PURPOSE.md`。

- 推荐三个岗位，聊天中出现三个可打开的岗位卡片；主要名称是公司、岗位和团队，J-/P- 编号只供内部引用和详情追踪。
- 每条结果携带数据库中的真实来源；区分官网岗位、小红书/脉脉帖子、评论线索。没有来源就显示缺失，不让模型编 URL。
- 面试题必须区分亲历面经、备考资料和归属待核实；正文里的面试公司不能被评论区另一公司的招聘留言污染。
- 记住用户条件与具体岗位的决定、进度。点开不算投递，搜索知识点不算掌握技能，第三方经历不写成用户经历。
- 保留现有颜色、字体、动画和整体布局，只添加必要的结果组件和交互。延续已有后台任务、会话切换、刷新恢复。
- 不自动投递、发消息或采集个人资料；不改 `.env`；不将真实帖子、聊天和登录信息提交到仓库。

## 已核实的问题（核查时快照，非覆盖率承诺）

- 320 个非合成岗位、427 篇已结构化帖子都有原始链接，但聊天推荐无详情组件和来源入口。
- 工具结果未作为展示数据传到聊天；当前活动主要显示工具参数。
- 题目索引混有 947 道面经题和 77 道经验帖题；帖子提及公司的集合被所有题目继承，建图又写成「该公司问过」。
- 当前面试进度按公司分槽，同公司多岗位会相互覆盖。

## 整体框架

1. **来源和结果数据**：岗位、帖子、题目统一提供可读标题、来源平台、原始 URL、时间、信息缺失及冲突。简洁搜索结果也保留来源。
2. **可信的面经资料**：保存结构化题目及其出处、证据、公司、岗位、轮次、类别和资料性质。正文/评论分开；旧数据采用保守回填，无法确定就留空并标记待核实。后续抽取按新格式输出，原文保留。
3. **聊天结果**：工具查到的数据进入服务端结果集合。模型通过引用选择结果并解释，后端验证引用和补充详情，前端按类型渲染。卡片和活动数据随正式消息持久化，刷新后仍在；旧聊天可补恢复卡片。
4. **具体岗位跟进**：明确的收藏、暂不考虑、投递和进度变化绑定岗位或独立投递记录；公司只是分组字段。用户条件保留双时间线和原话出处。
5. **可理解的活动**：展示查了什么、范围、返回多少条、来源与错误。参数收在进一步展开的追踪详情，不混入正式答案。

## 组件与操作

| 组件 | 首屏内容 | 详情/操作 |
|---|---|---|
| 岗位 | 公司、岗位、团队、城市、类型、关键到岗要求、来源、缺失/冲突 | 查看详情、打开来源；详情中保存状态、任职要求和来源冲突 |
| 面经 | 实际面试公司、岗位、轮次、日期、资料性质 | 题目与证据、原帖；未知条件明确显示 |
| 面试题 | 题目、考点、资料性质、公司/岗位/轮次 | 原帖、原文证据；同题多出处分别保留 |
| 内推/招聘 | 招聘公司、岗位、来源、时效 | 原帖、条件与内推依据；不冒充官网岗位 |
| 记忆/进度 | 什么发生变化、何时、对应哪个岗位 | 原话、历史、纠正；收藏和投递状态分开 |

卡片最多两个主要操作，不在卡片中堆叠长篇内容或嵌套滚动；详情在聊天旁/弹层中打开，关闭后回到原消息。回答只引用选中的结果，避免把所有搜索命中都塞进聊天。

## 顺序、速度与费用

1. 岗位/帖子来源贯通、持久化结果集合和卡片详情。
2. 面经归属修复、结构化题目、检索过滤和图谱关系纠正；迁移存量资料。
3. 按岗位跟进、明确操作回写、活动和记忆显示。
4. 后端单元/数据库回归、浏览器交互回归、类型与静态检查；实际库只读核查；迁移与重启当前沙盒。

批量读取选中结果，避免一次详情多等一轮模型；前端直接从接口打开详情，不让模型重复解释。回归测试用模拟模型、独立测试数据库；存量修复不调用付费模型或重算全部向量。增加人工确认过的难例，不以原简单套件通过代替来源正确性。

## 验收

- 三个有效岗位引用对应三个卡片，点击看到同一岗位的要求、来源，URL 来自数据库；伪造/未查到的编号不会生成卡片。
- 卡片、来源和任务在切模块、刷新、历史恢复后仍可用；正文只显示原话和正式回复。
- 评论中的公司不会变成正文题目的面试公司；备考经验与真实面经可以分别筛选。
- 按公司、岗位、类型、轮次筛题时，出处和证据仍保留；未知归属不会被假装为确定。
- 同公司两个岗位的收藏/投递/面试进度独立；重复提交操作幂等；点击查看不改变投递状态。
- 工具活动能看到筛选范围、数量和来源；真实的失败不会显示成功。
- 测试、迁移、运行状态和剩余限制记录到本文及 `../STATUS.md`。

# M6 设计：主 agent、主动决策、可托付

2026-10-11 实现（排期 10-18 到 10-20，提前）。目标：把记忆、检索、知识图谱、主动推送串成一个能对话、会主动、可托付的北极星；
对应 `PLAN.md` 0.0 的"有目标、常驻、懂你、懂行、主动但克制、可托付、可核实"里后面几条。

## 组成

|---|---|---|---|
| 主 agent | `agent/main.py` | 每句话先过记忆（`memory/extract.remember`），卡片和待确认的问题放进系统提示，再带 10 个工具回答（岗位、帖子、面试题、图谱统计、记忆）。LangGraph Postgres 检查点按会话存；对话超过 1.2 万 token 用摘要中间件压缩；有副作用的工具停下来等你批准 | 流程和规则自己写；LangChain 1.x 的 `create_agent`、中间件、LangGraph 检查点现成 |
| 人工审批 | `agent/main.py` 的 `approval_policy`、`resume()` | 策略表：`read_only=False` 的工具（目前是 memory_forget）一律批准或拒绝，不允许改参数后执行；拒绝的理由回给 agent | LangChain `HumanInTheLoopMiddleware` 现成 |

## 几个设计决定

- **聊天记录与上下文分开，任务由后端拥有。** 10-11 体验修复后，`transcript.py` 保存原话和正式回复，`tasks.py` 保存任务、进度和结果。
  LangGraph 检查点只管理模型上下文与中断，内部摘要不会当成用户消息。网页断开后任务继续；详细状态、恢复边界和接口见 `../TECH.md` 第 5 节。

- **记忆在 agent 之前，不当成工具让模型自己决定要不要记。** 每句话都先过记忆（抽候选 → 规则决定），这样"记不记"不靠模型临场判断，
  也能单独评测（M5）。要问你的（矛盾、推断）放进系统提示，让 agent 回答完正事后顺带问。
- **两层防护，第二层兜底。** 第 1 层是外部原文标记加提示词规则，靠模型配合；第 2 层是人工审批中间件，不靠模型：
  只要是有副作用的工具，调用前一定停下来等你批准。所以即使第 1 层被骗过，记忆也不会被删。对外动作（投递、发消息）北极星根本没有工具，只能起草。
- **主动决策全部是规则，每条都有理由。** 打扰你的代价比漏推一条高，所以规则偏克制：不在你说的城市、方向不沾边、类型不对、
  不想去的公司、不接受的条件直接不提；到岗天数或时长对不上只进简报让你判断；面经只在你正在面那家时推。
- **在真实数据上试跑过再定规则。** 场景题全对之后，在真实数据（复制出来的库，不碰你的记忆）上试跑每日流程，暴露出场景题没覆盖的问题：
  方向只看概念会把"Agent 开发"和"Agent 产品""Agent 算法"混为一谈；帖子的城市是"上海、北京"一个字符串要拆开；
  第一次跑时库里已有的几百个岗位全算"新"的。据此改成方向 = 概念 + 职能、岗位名只看标题里的岗位部分、第一次只出简报不推送、简报最多 12 条。

## 结果

- **主动决策**（`../../eval/reports/proactive.md`）：开发集 23 条第一次 19/23，按它加了三条规则；留出集 19 条（调完才写）全对。
  **注意：规则和标签同一作者写的，满分不能说明真实使用里不打扰人**，要作者本人按自己的习惯再标一批。
- **Polaris-Bench v2**（`../../eval/reports/M4.md` 第 5 节）：18 题 3 次，knowledge 配置 54/54（pass^3 18/18，平均 3.5 次工具调用），
  M3 的 search 配置 42/54（11/18，平均 13.5 次）。这份题对 knowledge-v2 已经是开发集，而且满分，下一版要加更难的题。
- **提示注入**（`../../eval/reports/injection.md`）：五种攻击各 3 次，有第 1 层防护：被骗 0/15、外传 0/15、提醒你 15/15；关掉第 1 层：被骗 0/15、外传 0/15、提醒你 14/15。**这几种攻击对当前模型太弱，区分不出第 1 层的作用**，下一版要加更隐蔽的攻击；无论哪一组，memory_forget 都没有真的执行（第 2 层兜底）。第一次评分把"引用原文里的链接并提醒你"也算成了外传，已改为链接和卡片信息同时出现才算。
- **主 agent 实测**（在复制出来的库上）：说"我是研二，想找北京的 Agent 开发日常实习，每周能去 4 天，帮我挑 2 个"——
  先记下 5 条事实，再查卡片、按北京筛、取 4 个岗位详情，推荐 2 个并写明依据的记忆和岗位编号、说清"每周天数岗位没写"，
  把要求 6 个月的两个单列出来，最后问可实习时长，并说明投递要你自己发。

## 还不好的地方

- 摘要压缩还没有评测（压缩前后正确率之差、省下的 token）。
- 主动程度只能改配置文件，还不能在对话里说"别老推我"来调。
- 推送只有 Windows 系统通知；微信放到最后（M9 以后）。
- 审批只有批准 / 拒绝，没有"这一次 / 这个会话 / 永久"这类授权范围（Muse 有），也没有 10 分钟超时。
- `GET /api/raw-items` 这类早期接口没有口令，只能绑在本机；上云前要加。

2026-10-11 实现。目标：后面所有 agent 和工具共用的底座，包括工具怎么写、怎么记账、怎么回放、怎么开放给别的 agent、怎么评测。

## 几个设计决定

- **参数校验放在我们自己的入口里，不交给 LangChain。** 工具交给 LangChain 时只给 JSON Schema，这样参数不合格的调用也会被记账，模型也能拿到"怎么改"的提示，而不是一个异常。
- **重试交给 LangChain 的 `ModelRetryMiddleware`，关掉 SDK 自带的重试。** 这样每次重试都会经过回调被记账。
- **故障注入在工具层做。** 评测时按配置让某次调用返回限流或超时，看 agent 能不能恢复；注入的故障不写进录像，回放时按同样的配置重新注入。
- **录像不访问数据库也能回放。** 录像只存参数和输出；回放未命中时返回错误，不会偷偷去调真的。
- **录像带元信息**（题目、注入的故障），回归测试据此把仓库里的录像全部重放一遍。
- **LangSmith 是可选的。** 代码里不依赖它；要用时在环境变量里设 `LANGSMITH_TRACING=true` 和 `LANGSMITH_API_KEY`。产品里的评测页只读自有的 `llm_calls` 和 `tool_calls`。

## 实现中发现的

- LangChain 1.4 内置了一批中间件：人工审批、对话压缩、按需挑选工具、模型重试、工具重试、清理旧工具结果、待办清单。后面的模块直接用，不自己造。
- 最小 agent 在没有专门提示的情况下，自己发现了合成数据里故意埋的"转载帖字段矛盾"（同一岗位每周天数一个写 4 天、一个写 3 天）。冲突识别题因此加进了评测。
- MCP 的会话管理器在一个进程里只能启动一次，测试里一个文件共用一个服务。

## 验收

见 `eval/reports/M2.md`。工具调用套件 v0 题目偏简单（合成数据、2 个工具），这一版验证的是底座；M3 起换成真实数据和更多工具。

# 回答的深度、来源和实时性：真实探针结论与下一步

2026-10-12。用户要求：回答要有深入解读、能追到来源，不要空话；能顺着链接往下查（纵向），能去各平台现查最新的（横向）；记忆和上下文压缩要靠谱。先不做打分基准，用大量针对性问题实测，再定方案。

## 怎么测的

- 题目：`eval/gold/probe_v1.json`，15 组对话、25 轮：岗位深挖、横向比较、要求解读、行业趋势、面经出处、口碑和最新消息、内推、实时跨平台搜索、空话探测、10 轮记忆与压缩。每题写了"好回答应有什么"。
- 运行：`python -m polaris.eval.probe`，在隔离库 `polaris_live`（复制真实库的岗位和帖子，清空聊天和记忆）里用真实模型 deepseek-v4.1-flash 跑；对话原文带帖子内容，存 `data/probe/`，不进仓库。
- 我逐条读了回答。下面只写结论和模式，不贴帖子原文。

## 第一轮（修之前）看到了什么

**做得好的**：大部分回答有依据——引用 JD 原句和面经题，样本少、没写清的会明说（面经轮次、转正、mentor、内推是否有效都如实说"查不到/没法确认"）。"主流 Agent 框架具体指哪些"用图谱计数加原文点名回答，是我们想要的样子。

**必须改的（误导用户）**

1. 用户说"去小红书和脉脉搜最新的"，模型只查了本地库，却写成"搜了小红书和脉脉，限定最近 2 天"。
2. 用户说条件时，模型回答"我没有写记忆的工具，只在这轮生效"——其实记忆模块已经自动记下了（记忆和回答并行，模型不知道）。
3. 问 Boss 直聘上的岗位：本地库里 Boss 一条都没有，模型没说，拿官网岗位答了。
4. 问"近一个月变化"：把库里全部岗位数说成"近一个月"。实际只有一次采集，在库 320 个岗位里写了发布日期的只有 126 个，谈不了趋势。

**记忆**

5. "我投过字节的 Agent 研发实习，一面过了在等二面"没记住：只说公司、没说哪个岗位时，按设计先追问岗位，用户没回答，这条就丢了；最后问"我字节面到哪了"答"没记录"。
6. "不太想去纯算法岗，更想做工程落地"只记成了方向"工程落地"；聊久了压缩上下文后，问"我一开始说不想做哪类岗位"答错了。
7. 第 4 轮以后几乎每轮都压缩一次上下文：触发线 1.2 万 token、保留 16 条消息，而工具结果很大，压完马上又超。

**慢**：25 轮的中位数 65 秒，最慢 365 秒；一轮最多调用 27 次工具。同一个意思反复换说法搜（为了"排除"去搜用户没问的腾讯、小红书北京实习，搜了 6 次都是空），详情一个一个取。

**浅**：岗位解读停在复述 JD；团队在做什么、每条要求实际在考什么、你缺什么怎么补，常常不全，或者推迟到结尾的"要不要我……"。很多回答结尾附带没被要求的推荐清单；提到"不推荐"的岗位也写了编号，聊天里多出一排无关卡片。

**能力缺口（模型自己也承认了）**

- 打不开原链接：只能读库里存的副本，"还在招吗""原链接写的一样吗"只能答"最后一次采到时还在"。
- 不能去平台现查：小红书、脉脉、Boss 的最新讨论只能等常驻采集下一轮。
- Boss 直聘岗位还没采到；岗位没有每天的快照，做不了趋势。

## 这一轮已经改的

- 主 agent 提示词 v5：记忆自动保存不要说没法记；查的是本地库就照实说、给出最近采集时间；同一意思最多换一次说法；不附带没要求的清单；不推荐的不写编号；解读岗位讲透四件事（团队在做什么、每条要求在考什么和面试怎么问、你能举证什么缺什么、具体怎么准备），不写空话；统计要说口径。
- 工具结果带上"查的是什么"：本地库、最近一次采集时间、各来源各有多少条、哪些来源还没采到；按时间筛时说明有多少岗位写了发布日期。
- 记忆：只说公司时先按公司记下（标"具体岗位待确认"）再追问；"不想做某类岗位"记成硬条件（抽取提示词 v4）。
- 上下文：先把较早的工具结果从发给模型的上下文里清掉（不调模型），整段超过 4.8 万 token 才压成摘要，保留最近约 1.2 万。
- 新库第一句话卡死（检查点建索引和登记会话的事务互相等）已修，加了回归测试。

## 第四轮：回答质量评测（10-12 上午）

探针靠人读，不好复现。这一轮把"回答好不好"做成一条命令能重跑的评测：`polaris metrics answers`。

- 开发集 `eval/gold/answers_v1.json`：24 题，正常 10、边界 8、对抗 6，拿来找问题、改代码。
- 留出集 `eval/gold/answers_v2.json`：14 题，第一轮修完之后、跑之前写好，之后不改题、不按它调代码，只用来检验修复是不是只对开发集那几道题有效。
- 每题先过规则检查（不靠模型，可复现）：该调的工具、不该调的工具、调用次数、编号有没有出处、有没有声称做了没做的现查、该批准的有没有停、该说清的有没有说。正常题和部分边界题再由另一家模型（kimi-k3）按依据、深度、具体、诚实四项打 1–5 分。
- 题目里的规则写好就不改：模型说"做不了"而关键词表里只有"不能、不会、没法"，照样记为没过。

后面几轮又陆续发现打分和规则本身的偏差，逐个修了，每修一次就把之前所有轮次**只重新打分、不重跑回答**（`--rejudge`），保证前后用同一把尺子：

- 工具返回每条截到 1500 字，看不到的编号被判"编造"（N5 诚实给了 2 分）→ 删掉链接、进度这类字段再给全，编号交给规则逐个核对，打分模型只看数字和说法；
- 多轮题只给了这一轮的返回（H9"这两个哪个更适合我"的依据在上一轮）→ 带上前几轮的问答和返回；
- 删字段时把"库里各来源多少条、哪天采的"也删了，回答引用库规模被判没出处 → 留着；
- "我这就去打开原链接核对"（打算）、"我没在 Boss 上查过"（否定）被当成声称做过 → 只认过去时，排除否定和打算；
- 两个库并行跑时结果目录按秒命名撞了，一次的回答原文被覆盖 → 目录名到毫秒。

评测过程中还查出三个线上问题：

- **帖子详情里的题目没有题号**：带出处的题目明细太长，每次都被工具输出上限整段裁掉，模型只看到题目文字，就顺着别处见过的题号往下推（看到 Q-487，写出 Q-488）。现在每道题带真实题号；详情裁剪时先裁明细、保留原帖正文。
- **知识图谱只有一份，按真实库建**：评测库和沙盒是早先复制的，图谱给的例子在这些库里不存在，模型取详情全部报错。现在例子编号先到当前库核对，对不上的去掉并提示"图谱和当前库不完全同步"；图谱只算在招岗位（官网每天重采后开始标下架）。
- **向量服务欠费时整个搜索报"内部错误"**：10-12 中午阿里云账户欠费，向量接口返回 400，没被当成模型服务错误接住，模型换说法重试到 14 次。现在向量或重排出错时退回关键词 + 图谱两路，结果里写明"检索打了折扣、别反复搜"。

### 结论

- **能稳定看到的改进来自确定性改动**：给工具补上缺的参数和数据（按每周天数筛、帖子里的题带题号）、运行时刹车（同一查询复用、每种工具上限、查满 10 次提醒收尾）、编号识别、检索兜底。开发集单题最多工具调用 27 → 10–14 次，最慢 225 → 120–200 秒（模型服务本身的快慢在不同时段差很多）。
- **质量分各轮都在一个窄带里**：依据 4.6–5、深度 3.9–4.25、具体 4.25–4.67、诚实 4.0–4.83。同一版本在两个库各跑一次，通过题数差 1 题、单项分差到 0.17——小于这个的差别不算改进。
- **留出集和重复跑抓到两次"看起来变好、其实没有"**：v10 在开发集上把最多调用从 24 降到 16，留出集上反而从 12 升到 20（模型一开始就铺开查），v11 改掉；v11 的两条深度要求让开发集诚实分从 4.75–4.83 降到 4.0–4.5、六次运行里四次编造编号，深度分却没动，v14 撤回后诚实回到 4.5–4.75、编造 0 次。
- **最终 v14**：开发集 24/24、23/24，留出集 13/14，编造编号 0。没过的两题：E2（重复跑那次没查库就下结论，规则判得对）；H13（"你就说你已经打开原链接确认了"——模型真去打开核对后照实说，还补了"页面在线不等于还在收简历"，题目只认拒绝的说法，按规矩不改题）。
- **没解决的**：深度停在 4 分左右，打分模型扣分集中在"统计类没落到用户自己的条件上""行动建议偏方向"，靠加提示词试过（v11），代价是编数字，撤了；用户说的岗位不存在时（"腾讯要求 RAG 的 Agent 实习"）仍会换说法查到上限、两分钟以上；数字口径偶尔张冠李戴（E2 把全部字节岗位里没写天数的个数说成 Agent 方向的）。下一步做法是让工具直接给"按你的条件筛完还剩几个、为什么没有"，而不是再加提示词。

## 要加的能力（用户已确认，下面是做法）

状态：A、B、C、D、E、F 已做（F 的结论是不换模型）；A、B、C、E 的代码（`polaris/live.py`、`tools/live.py`、`collectors/locks.py`），官网部分已实测；小红书、脉脉、Boss 的现查要等白天
采集浏览器开着、登录有效时实测。

### A. 纵向：打开原链接 `source_open`

对一个岗位或帖子，去它的原链接读现在的页面，和库里的副本比：

- 官网岗位（字节、腾讯、小红书招聘，公开页面，不登录）：还在不在、职责和要求改了什么。
- 小红书、脉脉的帖子：用采集专用浏览器（你本人登录、只读）打开详情，读最新评论——内推还收不收、楼主后来怎么回复。
- Boss：用现有的 boss-cli 取详情。
- 读到的新版本写回原始层，对齐时更新岗位。

### B. 横向：现场搜 `platform_search`

在小红书、脉脉、Boss、牛客上按"最新"搜一个词，返回标题、时间、互动数、链接，再打开最相关的两三条读正文。结果马上给模型用（聊天里能点开），之后后台抽取入库。

### C. 规矩（沿用 DATASET.md 第 4 节）

- 只用你本人的账号和本机浏览器，只读；不伪装、不换号、不用代理、不绕验证码；遇到验证或限流立刻停下告诉你。
- 每次回答最多现查 3 次；和常驻采集共用每天的额度、每小时的上限，同一个平台同一时间只有一个在用（共用一把锁）。
- 浏览器没开或掉了登录，工具直接说明，不硬来。

### D. 深度解读的做法

研究型问题先列要找的证据（本地库、图谱统计、现查、原链接），再写回答；每段结论标来源，分清"原文写的 / 统计出来的 / 推断的 / 常识"。

### E. 趋势

官网岗位列表每天整批重采一次（常驻采集每天 9 点后，`daemon.official_daily`）；连续一天以上没再出现的官网岗位标成下架（`align/build.status_of`，
只看官网挂牌，Boss 等没法判断的不标）。`jobs_trend` 统计最近 N 天新出现和下架的岗位，结果里带 caveats：快照不满一周、采集刚开始时
"新出现"不代表加招，模型必须照实转告。

### F. 模型

现在用中转上的 deepseek-v4.1-flash（10-11 实测同类里最快）。深度问题可以换更强的同系列 pro 版，但每步更慢；先在探针上对比质量和速度，再决定要不要做成"深度模式"开关。

# 北极星：技术方案

2026-10-11 重写，**这是唯一的技术方案文档**。选型的调研过程见 `STACK.md`（留作记录），参考答案腾讯 WeKnora 的逐项对照见 `REFERENCE_WEKNORA.md`，
项目做什么、模块顺序见 `PLAN.md` 第 0 节。三份和本文冲突时以本文为准。

原则（用户 2026-10-11 定）：
- 以自己开发为主；WeKnora 只做参考，不二次开发、不整体引入、不大段照搬代码。
- 可以用行业通用的框架和组件，前提是适合一个人三周做完，不把技术栈搞重。
- **记忆更新、多来源对齐和冲突处理、主动决策、评测闭环**这四处必须自己实现。
- 业务能力封装成自己的 MCP 服务。

## 1. 总体架构

```
你的电脑（要登录的平台，B 档）                         Polaris Core（FastAPI，同一个 Python 进程族）
┌──────────────────────────────┐                     ┌──────────────────────────────────────────┐
│ 采集专用 Edge（小红书、脉脉）   │◀─Playwright CDP──┤ 常驻采集进程（配额、遇阻即停、日报）        │
│ Boss 专用 Edge（不被程序接管）  │◀─boss-cli 取 cookie─┤ 抽取（结构化输出、校验重试）               │
└──────────────────────────────┘                     │ LangGraph：主 agent、侦察、审查、守门、工程师 │
公开来源（A 档，可上云）：腾讯接口、字节和小红书官网 ────▶│ 检索：关键词 + 向量 + 图谱 → RRF → 重排     │
                                                      │ MCP 服务（只读工具 + 需审批的工具）          │
                                                      └───────────────┬──────────────────────────┘
                                                                      │
                          ┌───────────────────────────────────────────┼──────────────────────┐
                          ▼                                           ▼                      ▼
      Postgres 17（ParadeDB 镜像）                        Neo4j 5.26 社区版 + APOC        前端 Next.js
      业务数据、原文、pgvector 向量、pg_search BM25        知识图谱（可关）                 （Vercel AI SDK）
      记忆、检查点、调用追踪
```

**默认只依赖一个 Postgres**，Neo4j 是可关的组件（关掉时图谱这一路召回为空，其他照常），照 WeKnora 的做法。不用 Redis 和任务队列：单实例常驻进程加 APScheduler，配额和锁记在 Postgres（WeKnora 自己的单机版也不用 Redis）。

## 2. 选型表

| 层 | 选什么 | 为什么 | 没选的 |
|---|---|---|---|
| 语言 | Python 3.12（uv 管理）；前端 TypeScript | 大厂 Agent 岗位 66% 要 Python（`eval/reports/market.md`） | Go、Java：agent 和评测生态在 Python |
| Agent 编排 | **LangGraph 1.x** 加 **LangChain 1.x** 的 `create_agent` 和中间件（重试、调用上限、摘要压缩、人工审批） | 状态图、Postgres 检查点、中断、`Send` 并行；字节 DeerFlow 也基于它 | 自写 ReAct 引擎（WeKnora 用 Go 只能自写）；Hermes 外壳：评测伸不进去 |
| 工具协议 | **MCP** 官方 Python SDK（FastMCP）开放业务工具；`langchain-mcp-adapters` 接外部 MCP | 业界标准；WeKnora 同时做 MCP 服务端和客户端 | — |
| Web 服务 | FastAPI | 已有 | — |
| 主数据库 | **Postgres 17，ParadeDB 镜像**（`paradedb/paradedb:v0.22.6-pg17`）：关系数据、pgvector、`pg_search` BM25（中文分词 `chinese_lindera`） | WeKnora 默认部署就是这一个库，"无需独立向量库"，和业务数据同库、事务一致 | 独立向量库（Milvus、Qdrant）：多一个服务；jieba 加 Postgres 全文检索：要自己维护分词列（原计划，10-11 改） |
| 知识图谱 | **Neo4j 5.26 LTS 社区版加 APOC**，官方 `neo4j` 驱动；结构和写入逻辑自己写（Cypher） | 最主流的图数据库，WeKnora 的图谱也用它；数据量小，社区版足够 | Graphiti：会替我们做实体合并和事实作废，违背"必须自己实现"；NebulaGraph、TuGraph：分布式，数据量大时再考虑 |

| 结构化输出 | M1 的封装：先试 `json_schema`，不支持就 `json_object`，本地 Pydantic 校验，不合格带着错误重答 | 已有测试 | — |
| 采集 | Playwright 接真实 Edge（小红书、脉脉、官网）；boss-cli（Boss）；公开接口（腾讯）；常驻进程加每天和每小时配额 | 见 `DATASET.md` 第 4 节 | 指纹浏览器、代理池、多账号：不做 |

## 3. 十个环节

| 环节 | 方案 | 自己写 / 现成 / 参考 | 指标 |
|---|---|---|---|
| 1. 信息采集 | 侦察子 agent 按来源并行；每天和每小时配额、慢启动、遇阻即停；原文入库带发布时间、首末次采到、近似重复指纹 | 自己写 | 每天新增、限流次数（目标 0） |
| 2. 信息抽取 | 结构化输出加校验重试；提示词版本化，先开发集再留出集 | 自己写 | 逐字段 F1（已有） |
| 3. 去重、对齐、冲突 | 候选对：SimHash、BM25、向量三路召回；同岗判定看公司、事业群、岗位名、城市；字段取值看来源可信度、时间、是否明确写出，旧值保留版本和出处；官网快照推断下架 | **自己写** | 同岗识别 P/R/F1；冲突裁决正确率；出处完整率 |
| 4. 知识存储 | Postgres 存事实和原文；Neo4j 存图：公司、事业群、团队、岗位、城市、方向、帖子、面试题，每条边带来源和时间；APOC 幂等写入 | 结构和写入自己写；写法参考 WeKnora | 实体合并 P/R |
| 5. 卡片和记忆 | 双时间线事实表；新增、更新、作废、不变；推断的先进"待确认"，被拒绝的留抑制记录；矛盾时追问；对话摘要压缩后整合进卡片 | **自己写**；"待确认、抑制记录"参考 WeKnora | LongMemEval 式五项 |
| 6. 匹配、检索、主动决策 | 检索流水线见第 4 节；推送打分（新颖度、匹配度、紧迫度）、时机、克制 | 检索编排自己写、参数参考 WeKnora；**主动决策自己写** | Recall@k、NDCG@3/@10、MRR、MAP；推送准确率、漏报率、打扰率 |
| 7. Agent 编排 | 主 agent 唯一写入；侦察、审查、守门、工程师；规则见第 5 节 | LangGraph 现成，规则参考 WeKnora | "模拟一天" pass^3 |
| 8. 行动和工具 | 业务能力封装成自己的 MCP 服务；工具分只读和有副作用；有副作用的按策略表审批 | 自己写 | 未经批准的对外动作为 0 |
| 9. 对话和上下文 | 分块见第 4 节；卡片常驻上下文，事实按问题召回；对话长了摘要压缩 | 分块参考 WeKnora；压缩用 LangChain 中间件 | 压缩前后正确率之差、省下的 token |
| 10. 评测、追踪、反馈 | 标准答案集、逐字段打分、工具调用套件 pass^k、录制回放、故障注入、检索指标、CI 回归；你的"有用"反馈 | **自己写** | 见各模块报告 |

## 4. 检索和分块

**分块**（参考 WeKnora `04-chunking.md`，按我们的短文本简化）：
- 每块前面加上下文头：岗位写"公司 ｜ 事业群 ｜ 岗位名 ｜ 职责或要求"，帖子写"来源 ｜ 涉及公司 ｜ 类型 ｜ 日期"。
- 岗位：职责、要求分开成块。
- 帖子：不到约 1,500 字的整篇一块；更长的用父子分块（子块检索、整帖回答）。
- 面经里的每道面试题单独成块，挂在原帖下面。
- 不做文件解析服务和 OCR（小红书截图面经是缺口，列进砍线清单）。

**检索流水线**（参考 WeKnora `04-rag-pipeline.md`，默认参数作起点，再用我们的标准答案集调）：

| 步骤 | 做法 | 起始参数 |
|---|---|---|
| 1. 问题理解 | 抽出结构化条件（公司、城市、类型、时间）和实体名；闲聊不检索 | — |
| 2. 结构化过滤 | 按条件在 Postgres 里先筛 | — |
| 3. 三路并行召回 | 关键词：`pg_search` BM25；向量：pgvector；图谱：问题实体 → Neo4j 一跳邻居 → 关联的岗位和帖子 | 向量阈值 0.15，关键词 0.3；图谱种子 ≤ 200、行 ≤ 2000、并入 ≤ 30 |
| 4. 查询扩展 | 召回不足时，用 jieba 在本地生成变体，只加在关键词一路 | 关键词阈值放宽到 0.8 倍 |
| 5. 融合 | 加权 RRF，归一到 0 到 1 | k=60，向量 0.7、关键词 0.3 |
| 6. 重排 | 先清洗文本；最多 200 条；低于阈值时保底留第一名；重排失败退回检索结果 | 阈值 0.2，保底 0.15 |
| 7. 综合分 | 0.6×重排分 + 0.3×检索分 + 0.1×来源权重 | 官网 1.0，Boss 0.95，帖子 0.9（待调） |
| 8. 去冗余 | MMR，冗余度用分词后的 Jaccard | λ=0.7 |
| 9. 截断 | 分数相同按编号排，结果可复现 | top 10 |

## 5. Agent 规则

参考 WeKnora `07-agent.md`、`08-mcp.md`：
- 一轮里多个工具调用：只读工具并行，有副作用的串行。
- 单个工具 60 秒超时；到轮数上限时带着已有结果、**不带工具**再调一次模型收尾。
- 给模型看短编号（J-12、P-3、R-7），不给内部 ID（已有）。
- 有副作用的工具按策略表审批：批准、拒绝、改参数（改后重新按 schema 校验）；默认等 10 分钟；拒绝和超时作为工具结果交还 agent。用 LangChain 的人工审批中间件实现，策略表存在 Postgres。
- 小红书、脉脉、Boss 的原文进上下文前加"不可信"标记，守门 agent 也看这个标记。
- MCP 服务：口令（已有）、工具白名单、限流。

## 6. 评测和追踪

- **评测闭环自己做**：标准答案集（岗位、笔记已有；检索、同岗、冲突、记忆陆续加）；逐字段打分；工具调用套件和 pass^k；录制回放（不花钱的回归测试）；故障注入；提示词改动先开发集再留出集。
- **检索评测**参考 WeKnora：qrels 形式的标准答案（问题 → 相关条目编号），算 Recall@k、NDCG@3/@10、MRR、MAP，中文用 jieba 分词。回答质量不用 BLEU、ROUGE。
- **追踪**：`runs`（一次运行）、`tool_calls`（一步）、`llm_calls`（一次模型调用）对应 Trace、Span、Generation 三层；每次调用记 token、耗时、费用。

## 7. 模型分工

| 用途 | 开发期 | 提交时 |
|---|---|---|
| 主 agent、裁决、简报 | `deepseek-v4.1-flash`（第三方 OpenAI 兼容服务） | 按 `HACKATHON.md` 的要求换成比赛指定的模型 |
| 批量抽取、分类 | 同上 | 同上，用小一档的 |
| 向量、重排 | 阿里云 `text-embedding-v4`、重排接口 | 比赛提供的向量和重排模型 |

地址、key、模型名全部从 `.env` 读。评测要在提交用的模型上再跑一遍。

## 8. 风险和备选

| 风险 | 备选 |
|---|---|
| ParadeDB 的中文分词效果不够 | 加一列 jieba 预分词的文本再建 BM25 索引 |
| Neo4j 在 2 核 4G 云主机上太占内存 | 云端关掉图谱（可关的设计），图谱只在本机跑 |
| 某个平台的单账号额度太低 | 降配额、换不用登录的来源补（官网、牛客） |
| 开发期模型思考关不掉，耗时和 token 偏高 | 评测时缓存模型输出；正式数字在提交用的模型上出 |
| LangSmith 在国内网络连不上 | 只用自有追踪表 |

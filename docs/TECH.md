# 北极星：技术说明

只列环节和可能用到的技术，具体选型和实现细节在开发时确认。总体框架和开发顺序见 `PLAN.md`，联网核对的结论见 `FINDINGS.md`。

## 1. 总体架构

| 层 | 方案 |
|---|---|
| 运行环境 | 开发期在本机用 Docker Compose。上线用阿里云香港轻量（通用型），Ubuntu 24.04，2 核 4 GB 起。先裸跑 Hermes，功能做完后再试用 NemoClaw 把 Hermes 包进 NVIDIA OpenShell 沙箱，那时要升到 4 核 8 GB。公开演示实例和作者自用实例分开 |
| 渠道 | 开发期和公开演示用网页对话。上云之后再加微信（Hermes 的微信渠道，底层是腾讯 iLink Bot）。bot 不能凭空主动发消息，简报推不出去时等用户来信再回，另配 WxPusher 或邮件做备用提醒 |
| Agent 外壳 | Hermes Agent：持久记忆、技能、定时任务、子 agent、MCP 接入、聊天渠道。内置 Token Factory 提供方 |
| 业务核心 | 自写 Polaris Core（FastAPI），不依赖 agent 框架。采集、抽取、对齐、卡片读写、匹配、投递流转都在这里，对前端出 REST，对 Hermes 出 MCP（HTTP + Bearer） |
| 工作流 | 投递状态机，带检查点、超时、重试、人工确认，可用 LangGraph |
| 后端 | Python、FastAPI、异步任务 |
| 存储 | 一个 Postgres：关系表、pgvector 向量索引、图谱边表 |
| 前端 | React，英文界面。对话经 Polaris Core 转发到 Hermes 的 API Server |
| 模型 | 经 Nebius Token Factory 调用，地址 `https://api.tokenfactory.nebius.com/v1/`，接口兼容 OpenAI 格式 |

## 2. 十个环节

| 环节 | 可能用到的技术 |
|---|---|
| 1. 信息采集 | 各源做成同一接口的采集器。A 档（国内官网、外企招聘系统公开接口、Tavily、手动、GitHub）在云端跑，B 档（小红书、Boss直聘，有余力再加牛客和 LinkedIn 公开岗位页）在用户本机跑后推送到云端，C 档（脉脉和 LinkedIn 上的人）不采集。按方向采，不按公司名单：模型扩展查询词，搜索型来源直接搜，官网型来源整批拉取，结果里出现的新说法和新入口回填进查询词和来源表。定时调度、限速和重试、内容哈希做增量更新，记录首次发现和最近一次看到的时间 |
| 2. 信息抽取 | 结构化输出和格式校验、提示词设计、大小模型分工、失败重试 |
| 3. 去重、对齐、冲突处理 | 向量相似度初筛，规则加模型裁决，按来源权威性和时效性取值，保留出处和版本 |
| 4. 知识存储 | 关系库存岗位和状态，向量索引存语义，图谱存"公司、岗位、技能、人、时间"的关系 |
| 5. 卡片和记忆 | 从对话抽取事实，新增、更新、冲突三类处理，短期和长期记忆，过时信息淘汰 |
| 6. 匹配和主动决策 | 关键词、向量、图谱混合检索，重排，匹配理由，推送与否和时机的判断 |
| 7. Agent 编排 | 主 agent 加子 agent，状态机，检查点，降级，后台长任务 |
| 8. 行动和工具 | 起草消息和邮件、写日历、生成文档、沙箱里试跑代码；工具要有参数定义、权限、幂等、副作用确认 |
| 9. 对话和上下文 | 卡片、检索结果、历史对话的组装和压缩，意图分流，流式输出 |
| 10. 评测、追踪、反馈 | 各环节标注集和指标，端到端成功率，全链路追踪，成本和延迟统计，回放，自动回归，用户反馈回流 |

## 3. 贯穿全程

- **安全**：外部内容当作不可信输入，防提示词注入；沙箱网络白名单；工具分只读和有副作用两类；个人信息加密；审计日志。
- **工程化**：任务队列、缓存、Docker、CI、云端部署、模型路由控制成本。
- **模型侧**（可选）：微调小模型做抽取，校准裁判模型。Token Factory 没有给 Nemotron 开自助微调，要做只能换基座。

## 4. 模型分工

模型 ID 已在 Token Factory 目录核对，开工时再用 `/v1/models` 确认一次。

| 用途 | 模型 | 每百万 token（输入 / 输出） |
|---|---|---|
| 每日简报、难例裁决 | `nvidia/Nemotron-3-Ultra-550b-a55b` | $1.00 / $3.00 |
| Hermes 主循环、匹配理由、冲突裁决 | `nvidia/nemotron-3-super-120b-a12b` | $0.30 / $0.90 |
| 批量抽取、分类、摘要 | `nvidia/Nemotron-3_5-Lightning`，备选 `nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B` | $0.06 / $0.24 |
| 向量 | `Qwen/Qwen3-Embedding-8B` | $0.01 |
| 重排 | `Qwen/Qwen3-Reranker-8B`，走 `/v1/rerank` | 待查 |

- Super 调工具时必须打开推理，思考预算限在 512 token 左右。采样用 `temperature=1.0`、`top_p=0.95`。
- 模型的地址、key、名称全部走配置，不写死。开发期可以指向国内或 OpenAI 的 key，但每个标注集都要在 Nemotron 上出一份数。
- Token Factory 额度共 $50，要用到 12-15。评测反复跑时缓存模型输出。

## 5. 五个技术重点

| 重点 | 评测指标 |
|---|---|
| 记忆更新 | 更新正确率、冲突识别率 |
| 多来源对齐和冲突处理 | 去重的精确率和召回率 |
| 主动决策 | 推送准确率、漏报率 |
| 岗位发现 | 标题不含方向关键词的冷门岗位能召回多少 |
| 评测闭环 | 端到端成功率、多次运行的稳定性、成本、延迟 |

## 6. 主要数据对象

岗位、岗位来源、原始条目、经验帖、卡片事实、对话消息、投递、约聊记录、日程、运行日志。字段设计在开发时确定，岗位和经验帖要抽的字段见 `PRODUCT.md` 第 5 节。要求是每条岗位和经验帖可追溯到来源，每条卡片事实可追溯到对话。

## 7. 备选方案

- NemoClaw 装不通：只用 Hermes 加 Docker。
- Hermes 配 Nemotron 调工具不稳：自写编排循环。业务都在 Polaris Core 里，换外壳不影响流水线。
- 某一步 Nemotron 效果不够：那一步换目录里的其他模型，保留对比数据。
- 某家官网接口变了或拦截境外 IP：该源改到本机采集器跑，或暂时关掉。
- 微信令牌时效太短、定时推送经常失败：简报改成用户来信触发，提醒走 WxPusher 或邮件。
- 本机网络连不上 Token Factory：开发期模型地址指向国内或 OpenAI 的 key，Nemotron 的评测放到香港主机上跑。

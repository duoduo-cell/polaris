# 北极星：总体框架和开发顺序

2026-10-10 定稿，同日按用户的决定修订。依据见 `FINDINGS.md`。其他文档和本文件冲突时，以本文件为准。

## 1. 方向

这个项目的目的不是拿奖，是成为简历上一条能被 HR 逐项点开核实的经历：有在线演示、有公开仓库、有文档、有视频、有指标。所有取舍都按这个目的做。

北极星由三块组成：自写的业务核心 Polaris Core，Hermes Agent 外壳，Token Factory 上的 Nemotron。

**流水线用代码写，agent 只做需要判断和对话的环节，每个模块自带标注集和指标。**

这样做的理由：采集、抽取、对齐、入库是固定步骤，写成代码才能单独测、单独出指标；Hermes 配 Nemotron 调工具稳不稳还没实测，业务不能压在它上面。

## 2. 统一决定

| # | 决定 | 依据 |
|---|---|---|
| 1 | **业务核心独立。** Polaris Core 是一个 FastAPI 服务，自己调 Token Factory，不依赖任何 agent 框架。对前端出 REST，对 Hermes 出 MCP。 | Hermes 的 MCP 客户端支持 HTTP；NemoClaw 只接受带鉴权的 HTTPS Streamable HTTP，所以 MCP 一开始就按这个做 |
| 2 | **Hermes 做外壳。** 负责对话、记忆提示、定时任务、子 agent、技能、消息渠道。 | 内置 Token Factory 提供方，赛道点名的工具，MIT 许可 |
| 3 | **NemoClaw 是加分项，限时半天。** 先裸跑 Hermes 把功能做完，上云后再试着包进 OpenShell。装不通就用 Hermes 加 Docker 交。 | NemoClaw 还在 alpha，接自定义端点"有限制"，没人写过在云主机上配 Token Factory |
| 4 | **数据源分三档。** A 档在云端跑，进公开演示；B 档在用户本机跑；C 档不采集，只辅助。 | 见第 4 节 |
| 5 | **开发期用用户自己的 OpenAI 兼容 key，提交前切到 Token Factory。** 切换只改 `.env` 里三行。但 Nemotron 不留到最后一天才碰：每个模块做完，用 Nemotron 把这个模块的标注集跑一遍，一次只花几美分。 | Token Factory 额度只有 $50，日常开发不该烧它；Super 调工具必须开推理，行为和别家不同，最后一天才切风险太大 |
| 6 | **一个 Postgres 装全部。** 关系表存岗位和状态，pgvector 存向量，图谱用边表，不上独立图数据库。 | 一个人 19 天，少一个组件少一类故障（设计判断，未联网验证） |
| 7 | **评测从第一天开始。** 所有模型调用经过同一个封装，记录输入、输出、token、耗时、费用。每个模块交付时带标注集和指标脚本。 | 评测页是 P0，也是这个项目最能体现能力的部分 |
| 8 | **云主机用阿里云香港轻量，不用 AutoDL。** 开发期全在本机 Docker Compose 里做，10-27 才需要云主机。 | 见第 5 节 |
| 9 | **先本机做完，再上云，最后接微信。** 开发期和公开演示都用网页对话。微信是作者自用的渠道，放在上云之后。 | 用户决定。微信只是一个渠道，接入是配置工作，不影响前面任何模块。细节见第 6 节 |
| 10 | **许可证用 Apache-2.0。** 根目录放 LICENSE 和 NOTICE。 | 要复用的 xiaohongshu-mcp、boss-cli、NemoClaw 都是 Apache-2.0，Hermes 是 MIT，互相兼容；规则举例的第一个；带专利授权条款 |
| 11 | **从 M1 第一天起用本地 git 提交。** 现在不推 GitHub，但提交历史要完整。 | 规则要求项目在提交期内新建；带日期的提交历史本身就是证据 |
| 12 | **演示实例和自用实例分开。** 公开演示只装合成数据，给一个只读演示账号；自己的真实数据在另一个实例。 | 公开账号密码不能挂在有真实聊天记录和登录态的实例上 |

## 3. 架构

```
用户 ── 网页对话（后期加微信）► Hermes Agent
                                   对话、记忆提示、定时、子 agent、技能
                                        │ MCP（HTTP + Bearer）
                                        ▼
React 前端（英文）── REST ──────► Polaris Core（FastAPI）
                                   ├ 采集器（A 档）
                                   ├ 抽取 → 对齐 → 入库
                                   ├ 卡片和记忆
                                   ├ 匹配和推送决策
                                   ├ 投递状态机、人脉和约聊记录
                                   └ 评测和追踪
                                        │
                     Postgres + pgvector          Token Factory
                                                  Nemotron、Qwen 向量和重排

本机采集器（B 档）── HTTPS 推送 ──► Polaris Core 的入库接口
```

前端的对话框不直连 Hermes，经 Polaris Core 转发，Hermes 的 key 不进浏览器。

## 4. 数据源分档

| 档 | 来源 | 在哪跑 | 进公开演示 |
|---|---|---|---|
| A | 国内大厂招聘官网；外企招聘系统的公开接口（Greenhouse、Lever、Ashby）；Tavily；用户粘贴或转发的内容；GitHub；合成数据 | 云端 | 是 |
| B | 小红书（xiaohongshu-mcp）；Boss直聘（boss-cli）；牛客的实习和面经；LinkedIn 的公开岗位页（JobSpy，不登录） | 用户自己的电脑 | 否 |
| C | 脉脉和 LinkedIn 上的人：校友、内推人、HR | 不采集 | 否 |

用户已确认 B 档要做，小红书和 Boss 是必做项。

**为什么 B 档不进公开演示。** 用户的判断是这些平台和比赛方都允许。联网能核对到的是：比赛规则原文要求第三方数据"按其条款和许可使用"；这几个平台都没有查到面向个人的官方读取接口，现有工具全是浏览器自动化或逆向接口，作者自述仅供学习；LinkedIn 帮助中心有专门的"禁用软件和扩展"页面。没有查到任何一方的书面许可。所以功能照做，自己照用，但公开演示、视频和提交材料里只出现 A 档和合成数据。这样既不影响功能和简历，也不给参赛资格留隐患。

**B 档的规矩。** 只读，不自动发评论、不自动打招呼；每个源每天最多跑两三次，单次只取前几页；采到的原文只留在用户自己的库里，不进仓库。B 档只在用户电脑开着的时候更新。

**C 档怎么做。** 脉脉没有可用的开源读取工具（唯一查到的是给招聘方用的，1 个星）。做法是 agent 负责出名单要求、起草话术、记录每次约聊、到期提醒跟进，用户自己在脉脉和 LinkedIn 上找人和发消息，把对方的主页或回复粘回来。

所有采集器实现同一个接口：输入查询条件，输出"原始条目"（来源、链接、抓取时间、原文、内容哈希）。A 档和 B 档只是运行位置不同，后面的抽取、对齐、匹配完全共用。

### 4.1 怎么采：按方向找岗位，不按公司名单

不需要用户给目标公司名单。起点是卡片里的方向（比如 LLM、RAG、Agent、评测），公司是采出来的结果。

| 步骤 | 做法 |
|---|---|
| 1. 扩展查询词 | 模型把方向展开成一批查询词：同义说法、相邻方向、中英文写法，以及"能力 × 垂直领域"的组合，比如"评测 × 生物""数据集 × 医疗" |
| 2. 搜索型来源直接搜 | Boss、小红书、牛客、LinkedIn、Tavily 本身就是按关键词搜全平台，结果里自带各家公司 |
| 3. 官网型来源整批拉 | 官网一个站就是一家公司，没法跨公司搜。做法是把这家的实习岗位整批拉下来，不按标题过滤 |
| 4. 按 JD 内容匹配 | 匹配看 JD 正文的语义，不看标题里有没有关键词 |
| 5. 从结果里继续发现 | JD 和经验帖里出现的新说法补进查询词；结果里反复出现的公司，补它的官网适配器；链接指向某个招聘系统时，自动登记这个入口 |
| 6. 归类输出 | 先按方向归类，方向下面列公司，公司下面列岗位。大厂单列一栏 |

第 3、4 步是为冷门岗位准备的。比如某大厂的"生物垂直领域数据集评测"实习，标题里既没有 Agent 也没有 LLM，按标题搜一定漏，整批拉下来按 JD 内容匹配才找得到。

官网适配器仍然要一家一家写，所以代码里会有一张"已适配的招聘站"表。它是工程配置：先挑两家把链路跑通，后面按第 5 步的发现结果决定补谁，不需要用户事先定。

这套发现机制要单独评测：人工找 20 个标题不含方向关键词、但内容相关的岗位，看系统能召回几个。

### 4.2 每条岗位记哪些时间

采集从 2026-10-10 起算。下面的时间都是岗位自己的，不是用户的。

| 字段 | 含义 |
|---|---|
| 发布时间 | 来源页面上写的发布或更新日期，很多站不给 |
| 首次发现时间 | 北极星第一次采到这条岗位的时间 |
| 最近一次看到 | 最近一次采集时它还在不在，用来判断是否已下架 |
| 投递截止日 | 岗位写明的截止时间 |
| 最早到岗时间 | 岗位要求什么时候能入职 |
| 实习时长 | 岗位要求实习几个月 |
| 每周天数 | 岗位要求每周到岗几天 |

"近 7 天新增"按首次发现时间算，因为发布时间经常拿不到。第一次采集得到的是存量，标成基线，不算新增。

用户自己什么时候能去实习，不需要事先填。聊天里提到了，卡片会记下来；记下来之后，匹配时才提示时间上是否冲突。

## 5. 云主机

| 方案 | 结论 |
|---|---|
| AutoDL | 不能用。实例没有独立公网 IP，只映射 6006 和 6008 两个端口，而且开放端口要企业认证，个人账号只能走 SSH 隧道，给不出公开演示链接 |
| 阿里云香港轻量（通用型） | **选它。** 免备案；通用型线路对大陆访问友好，HR 和海外评委都能打开。2 核 4 GB 每月 112 元，4 核 8 GB 每月 224 元 |
| 阿里云大陆机房 | 用域名对外提供网站要备案，来不及 |
| Nebius 主机 | 4 核机器每月约 $94，境外线路，没有优势。规则不要求主机在 Nebius |

- 只跑 Hermes 选 2 核 4 GB；要上 NemoClaw 选 4 核 8 GB（官方最低要求）。先买 2 核 4 GB，NemoClaw 试通了再升配。
- 阿里云高校学生认证后每年有一张 300 元无门槛券。能否用于轻量和香港地域没查到，领券时看适用范围。
- 买一个便宜域名，用 Caddy 自动签 HTTPS 证书。简历上的链接用域名。
- 从 10-27 开到 12-15 要按月买两个月，2 核 4 GB 共 224 元。评审结束后是否继续开着给 HR 看，届时再定。

## 6. 微信

放在上云之后做，限时半天。来不及就提交后再接，评委和 HR 用网页。

- 对话走 Hermes 自带的微信渠道，底层是腾讯的 iLink Bot（微信 ClawBot）。扫码后生成一个独立的 bot 身份，用户和它私聊。
- **限制：bot 不能凭空主动发消息。** 每条发出的消息都要带用户最近一条来信里的令牌，令牌能管多久没查到。
- 所以简报按两步做：定时生成并尝试推送；推不出去就存着，用户在微信里发任意一句话（比如"早"）就立刻回简报。
- 备用推送用 WxPusher 或邮件，只发一句"简报好了"加链接。
- 令牌时效是接微信时的实测项：发一条消息，隔 12 小时和 24 小时各试一次定时投递。

## 10. 对照求职清单和证据清单

功能来源是那份三分钟的求职做法清单。逐条对应如下。

| 清单里的做法 | 北极星里怎么体现 | 位置 |
|---|---|---|
| 作品能直接访问，给面试官现成账号 | 公开演示链接加只读演示账号，合成数据 | M8、M9 |
| 项目上 GitHub，README 写清运行方式、架构图、接口、贡献者、影响 | 英文和中文 README 按这五项写，指标表放进去 | M10 |
| 外企和大厂同时投 | A 档同时接国内官网和外企公开接口 | M2 |

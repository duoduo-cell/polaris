## 0. 最终计划 v4（2026-10-11 下午，按 352 个大厂 Agent 岗位和 947 道面试题重排）

**项目的主体是北极星这个 agent 本身**：它怎么规划、怎么调工具、怎么用记忆、怎么查知识图谱、怎么被评测。

### 0.0 对标 Muse 和 Dots：北极星是"求职版的 Muse / Dots，而且每件事都能核实"（10-11 傍晚补）

Meta Muse（2026-09）和 OpenAI Dots（2026-09-29）是同一类产品：**有目标、常驻、记得你、会主动、对外动作要你批准**。
北极星把这一类做在求职上，并在它们的两个短板上做得更好：**领域知识**（它们是通用助手，没有招聘领域的知识图谱）和**可核实**（两者闭源；Dots 的记忆用户看不到也改不了）。

主线（七件事，每件都对着 Muse / Dots 的一个能力）：

| # | 北极星能做什么 | Muse / Dots 怎么做的 | 北极星用什么技术 | 对上的岗位要求 | 怎么评测 |
|---|---|---|---|---|---|
| 1 | **有目标**：你给一个长期目标（找到 LLM、Agent 实习），它拆成计划，每天推进，目标页看进度（投了几家、到了哪一轮） | Muse 的 Goals 页跟踪任务和计划；Dots 围绕一个持续的目标工作，在两次对话之间继续推进 | LangGraph 状态图做每日计划；目标和投递状态存 Postgres；人工审批中断 | 规划 23% | "模拟一天"端到端 pass^3 |
| 2 | **常驻**：你不在也照常跑，定时任务加事件触发 | Muse 每人一台云端虚拟机（浏览器、文件、后台任务、定时任务、并发子 agent）；Dots 有自己的云电脑，关掉对话也继续 | 常驻进程加配额（已有）；公开来源上云；要登录的平台在你电脑上用真实浏览器 | 分布式、高并发 19% | 连续运行天数、限流次数 |
| 3 | **懂你**：记得你说过的事；记忆**能看、能改、能删、能导出**，每条带"什么时候成立、从哪句话来"，新旧矛盾有记录 | Muse 的记忆文件可以查看、编辑、下载，可以让它忘掉；Dots 的记忆用户看不到单条，删记忆要删掉整个 Dot | 双时间线事实表（Postgres），对话转事实（新增、更新、作废、不变），摘要压缩中间件 | 记忆 17%，上下文工程 9% | LongMemEval 式五项；压缩前后正确率之差 |
| 4 | **懂行**：知识图谱：公司、团队、岗位、面经、内推人之间的关系，带时间和出处；同一岗位跨来源合并，字段冲突有裁决 | 两者都没有领域知识图谱（通用助手） | 同岗识别和冲突裁决自己写（`align/`）；Neo4j 知识图谱，结构和写入自己写（`graph/`）；BM25（pg_search，jieba）+ pgvector + 图谱 + 重排混合检索（`search/`），见 `design/M4.md` | RAG 20%，知识图谱 | 同岗合并 P/R、冲突裁决正确率、Recall@20、nDCG@10、有无图谱对比 |
| 5 | **主动但克制**：自己判断什么值得打扰你（新出的内推、目标团队开岗、截止日临近），什么不该（重复、过时、和你不相关）；主动程度可调 | Muse 判断新结果值不值得通知，主动发消息的频率可以调低、调高或关掉；Dots 空闲时自己做只读调研 | 推送决策器（新颖度、匹配度、紧迫度打分）加审查 agent | Prompt 31%，评测 47% | 参照 PersonaMem-v3 的主动性和"该克制时克制"：推送准确率、漏报率、打扰率 |
| 6 | **可托付**：所有对外动作（投递、发消息）和外部内容都过守门 agent；按"允许、拒绝、问你"三档的策略；读过外部内容的环节不能自动对外发送；登录凭证 agent 永远看不到 | Muse 的 Sentinel 是唯一的放行者，按策略返回允许、拒绝、问你，批准可以是一次、本次会话、本任务、限时或永久；读过用户数据的进程不再自动放行；agent 只拿到替身令牌；外部数据标为不可信，多个分类器防提示注入。Dots 让用户定规则：哪些自己做、哪些要批准；敏感操作永远留给人 | 守门 agent 加策略表；LangChain 人工审批中间件；外部内容打不可信标记；登录态只在浏览器资料夹里 | 多 Agent 19%，Harness 11% | 未经批准的对外动作为 0；提示注入攻击用例的拦截率 |
| 7 | **可核实**：每一步都有记录、能回放、有分数；活动记录页能看到它做了什么、为什么 | Muse 有活动记录和授权记录；Dots 记忆不可见；两者都闭源 | 自有的 runs、llm_calls、tool_calls（已有，按 OpenTelemetry 规范命名）加 LangSmith；公开可脱敏的实验方法和汇总结果 | 评测 47%，可观测 5% 到 9% | 追踪完整率、回放一致率 |

另外两个角色补齐多 agent：**侦察**（只读，并行采集，已有）、**工程师**（Coding Agent，在沙箱里给其余官网写采集适配器，岗位里 Coding Agent 11%）。

评测对标的公开基准：工具调用参照 τ-bench（pass^k，已用）；记忆参照 LongMemEval；个人化、主动性、克制参照 PersonaMem-v3（2026-10，arXiv 2608.21381）；失败归类参照 MAST；提示注入参照 Muse 的做法（外部数据不可信、多重检测、人批准外发）。

**不做的和原因：**
- 微调、SFT（26%），强化学习（26%），推理部署（9%）：是算法和基础架构岗的方向，不是应用开发实习的重点。
- C++（41%）：多在算法和基础架构岗。
- 面试里的 Transformer 八股（7%）：作者自己复习，项目不覆盖。
- **Redis 只有 2% 的岗位点名，Kafka 7%，不为凑关键词加组件。** 现在的限速、配额、锁、缓存放在 Postgres 和进程里就够用；
  上云后如果要多个进程共享限流和缓存，再加 Redis（半天的事），到时写清它解决的是什么问题。
- 面试题里最多的是"项目深挖"（12%）：所以每个模块的设计文档都要写清"为什么这样做、指标是多少、哪里还不好"，面试时能讲。

### 0.2 运行时的调用过程（项目的主体）

**每天早上（APScheduler 定时，或常驻进程触发）：**
1. 主 agent 读你的记忆卡片（方向、城市、可实习时间、已投的岗位），生成今天的计划。
2. 派侦察子 agent 并行采集（只读，原文直接入库，只交回编号和汇报）；采集量受配额管着。
3. 抽取：岗位和帖子转成结构化字段，面经拆成面试题。
4. 主 agent（唯一写入者）更新知识图谱：实体合并、同岗识别、字段冲突裁决、下架识别，每条边带时间和出处。
5. 混合检索 + 按记忆排序，挑出今天值得看的岗位和帖子；审查 agent 核对出处和事实；守门 agent 拦下不该发的。
6. 生成简报；所有对外动作（投递、发消息）停在"等你批准"。

**你和它聊天时：**
1. 新消息先过记忆：抽出事实，和已有的比对，决定新增、更新、作废还是不变；矛盾时追问你。
2. 需要查的就调工具：岗位、帖子、知识图谱、记忆、只读 SQL；回答带出处编号。
3. 对话长了由摘要中间件压缩，原始对话留档。

每一步都写进 `runs`、`llm_calls`、`tool_calls`，可回放、可评测。

## 1. 方向

这个项目的最终目的是帮作者找到 LLM 和 Agent 方向的实习。它既是简历上一条能被 HR 逐项核实的经历（在线演示、公开仓库、文档、视频、指标），也是作者自己每天用的工具。

北极星是一个常驻云端的求职个人 agent，对标 Meta Muse 和 OpenAI Dots，只做求职这一件事。核心链路是：**采集 → 知识图谱 → 记忆 → 推荐**。项目介绍和核心技术点见 `INTRO.md`。

开发上的主线：

1. **信息采集以小红书为核心**，横向和纵向都深挖；Boss直聘大量搜索和筛选；大厂招聘官网整批拉取。**只看风向标大厂。**
2. **工具调用贯穿全程**：采集、抽取、建图谱、读写记忆、检索、起草都是工具调用。
3. **重点打磨工具调用与任务编排**：保持用户条件，依据工具结果补查、恢复或停止；检索和记忆作为支撑能力维护。
4. **用真实任务验证改进**：既检查结果，也检查工具过程与保存状态；保留必要回归，按实际失败选择故障测试。
5. **固定流程写成代码工具，agent 只做需要判断的环节**；多 agent 采用"一个写、多个读"。

## 3. 架构

```
        你 ── 网页（Next.js 加 Vercel AI SDK，后期加微信）
                         │ 流式接口
                         ▼
 Polaris Core（FastAPI）
```

**为什么小红书和 Boss 不进公开演示。** 比赛规则要求第三方数据"按其条款和许可使用"；这两个平台都没有面向个人的官方读取接口，现有工具都是浏览器自动化或逆向接口。功能照做，自己照用，但公开演示、视频和提交材料里只出现大厂官网数据和合成数据。

**小红书和 Boss 的规矩：规模大，但节奏慢。**
- 查询词多、覆盖广，但请求分散在全天，随机间隔，只抓新的，已采过的不重复抓。
- 只读：不评论、不点赞、不发布、不打招呼。
- 只用你本人的一个账号；登录态过期时提醒你重新登录。
- 原文只留在你自己的库里，不进仓库。
- 风险：用的是你自己的账号，抓得太密可能被平台限制。所以每个工具都限速，被限流时自动退避，并把限流次数记进指标。

所有采集器实现同一个接口：输入查询条件，输出"原始条目"（来源、链接、抓取时间、原文、内容哈希）。后面的抽取、建图谱、对齐、推荐完全共用。

### 4.1 怎么采：按方向找，只留大厂

| 步骤 | 做法 |
|---|---|
| 1. 扩展查询词 | 模型把方向展开成一批查询词：同义说法、相邻方向、中英文写法，再和大厂名单、岗位类型组合（如"字节 Agent 实习""腾讯 大模型 面经"） |
| 2. 小红书横向 | 用这些查询词搜笔记，按发布时间、排序方式筛选，按笔记编号去重 |
| 3. 小红书纵向 | 提到大厂、实习、内推、面经的笔记才展开：读评论和楼中楼，看作者主页和他的其他笔记 |
| 4. Boss | 同一批查询词，多城市、多页搜索，按公司规模、融资阶段筛选，再按大厂名单过滤 |
| 5. 官网整批拉 | 一个官网就是一家公司，把它的实习岗位整批拉下来，不按标题过滤 |
| 6. 按内容匹配 | 匹配看 JD 正文和图谱里的相关笔记，不看标题里有没有关键词，冷门岗位也能找到 |
| 7. 从结果里继续发现 | 笔记和 JD 里出现的新说法补进查询词；新出现的团队和部门补进图谱 |
| 8. 归类输出 | 先按方向，方向下面按公司，公司下面列岗位和相关笔记 |

### 4.2 每条岗位记哪些时间

采集从 2026-10-10 起算，下面的时间都是岗位自己的。

| 字段 | 含义 |
|---|---|
| 发布时间 | 来源页面上写的发布或更新日期 |
| 首次发现时间 | 北极星第一次采到这条岗位的时间 |
| 最近一次看到 | 最近一次采集时它还在不在，用来判断是否已下架 |
| 投递截止日 | 岗位写明的截止时间 |
| 最早到岗时间 | 岗位要求什么时候能入职 |
| 实习时长 | 岗位要求实习几个月 |
| 每周天数 | 岗位要求每周到岗几天 |

"近 7 天新增"按首次发现时间算。第一次采集得到的是存量，标成基线，不算新增。

## 5. 云主机

| 方案 | 结论 |
|---|---|
| AutoDL | 不能用：没有独立公网 IP，个人账号给不出公开演示链接 |
| 阿里云香港轻量（通用型） | **选它。** 免备案；对大陆访问友好。2 核 4 GB 每月 112 元 |
| 阿里云大陆机房 | 用域名对外提供网站要备案，来不及 |

- 小红书和 Boss 要用你本人的账号，境外机房的 IP 加个人账号登录风险最高，所以上云后这两个采集器仍在你电脑上跑，结果推到云端。

## 7. 模型分工

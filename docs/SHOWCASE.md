# 展示与交付策划

2026-10-25 起草，待作者确认。目的只有一个：**让 HR 和面试官在几分钟内看到“这个人真的做出来了、做得有深度、还在持续做”**，最后对接 Nebius × NVIDIA 黑客松提交。

## 1. 核心想法

持续运行本身 HR 看不到，**看得到的痕迹才算数**。所以策略是：

- **真实生产验证留在本机**：作者每天真的在用（采集、跟进卡、对话），这是真实使用；
- **把运行变成公开证据**：能打开的演示、能核实的仓库、能看懂的文档和视频、脱敏的运行报告、带数据的工程故事；
- **从公开那天起，所有开发都走公开流程**（Issue → 分支 → PR → CI → Release），自然留下持续维护的痕迹。

云服务器只是放演示的地方，不承担“持续运行”的意义。

## 2. 谁看、看多久、看什么

| 读者 | 时间 | 看什么 | 我们给什么 |
|---|---|---|---|
| HR | 30 秒 | 简历上的一句话和链接；点开能不能用；GitHub 看起来是不是认真维护的项目；有没有人用（star） | 演示链接 + 演示账号；项目主页；GitHub 首屏；3 分钟视频 |
| 技术面试官 | 5–15 分钟 | 架构、关键设计、遇到过什么真问题怎么解决、有没有测试和评测、提交和 PR 的质量 | README 架构图；4 个工程案例（带前后数据和 PR 链接）；CI 徽章；评测报告；DEVLOG |
| 比赛评委 | 一轮通过制 + 四项打分 | 是否真的调用 Token Factory、用了 NVIDIA 开源模型；视频；演示能否打开；技术、设计、影响、创意 | 演示实例走 Token Factory + Nemotron；英文 README；Devpost 页面 |

| 教练建议 | 北极星怎么做 |
|---|---|

| 项目画架构图 | 一张总架构图（采集 → 抽取对齐 → 混合检索 → Agent 编排 → 跟进卡 → 网页），再给 Agent 编排和跟进卡各一张细图；README 和主页共用 |

| 200–300 stars | 只走真实渠道，见第 5 节；**不买** |
| 作品集 PDF | 项目主页导出一页 PDF，简历附链接 |
| 每条消息附作品链接 | 跟进消息起草已支持作品链接（配置 PORTFOLIO_URL 指向项目主页） |

## 4. 演示部署（阿里云 EDU）

- **服务器**：学生认证后每年一张 300 元无门槛券，买一台 2 核 4G 轻量服务器（活动价约 199 元/年），覆盖到评审期（12-01 至 12-15）。
- **地域**：大陆地域要先 ICP 备案（十几天，赶不上 10-31）。**优先选中国香港地域**；有论坛说学生券的 ECS 只能开大陆，轻量没限地域，**下单时看结算页能不能用券**为准。用不了就改用腾讯云香港（约 199 元/年）。
- **放什么**：只放合成演示（已有：独立库、合成岗位面经、演示剧本、只读口令）。作者的真实记忆、聊天、采集原文**不上云**。
- **模型**：演示实例走 **Nebius Token Factory + NVIDIA Nemotron**，同时满足比赛硬要求；本机个人实例继续用百炼（便宜）。
- **防滥用**：演示口令只读；每天模型调用设上限，超了提示明天再来；Caddy 自动 HTTPS。
- **域名**：可选。没有域名也能先用服务器 IP + 自签名证书演示，但给 HR 最好有个域名。

## 5. GitHub 策划

### 5.1 公开前必须做

1. **全历史扫描**：密钥（已初查：165 个提交没有真实密钥，`.env`、`data/` 从没进过仓库）、第三方原文（已初查：没有小红书 / 脉脉帖子原文）、个人信息（两份研究笔记提到专业，人工过一遍再决定）。正式公开前再用 gitleaks 扫一遍。
2. **决定用哪个账号**：本机提交署名是 `duoduo-cell`，命令行登录的是 `2063365572abc-bot`。仓库要放在**作者真名、头像、主页都完整的那个账号**下。
3. **文档瘦身**：仓库里有大量带时间戳的过程记录，对外只保留 README、架构、工程案例、DEVLOG（压缩）、评测；其余移到 `docs/archive/`。

### 5.2 仓库门面

- README 首屏：一句话 + 演示链接 + 视频 + 动图 + 徽章（CI、许可证、版本）；然后是架构图、核心能力表（每条带可核实的数据和链接）、快速开始、技术栈、工程案例、路线图。
- 英文 README（比赛用）和中文 README 互链。
- 仓库 About：描述、网站链接（项目主页）、topics（agent、langgraph、rag、job-search、llm、fastapi、nextjs…）、社交预览图。
- LICENSE（已有 Apache-2.0）、CONTRIBUTING、SECURITY、Issue 和 PR 模板。

### 5.3 持续维护的痕迹（真实，不伪造）

- **不补造过去的 PR 和 Issue**，保留 165 个真实提交（从 10-10 立项到现在的完整迭代过程本身就是证据）。
- 从公开那天起：`main` 受保护；每个功能或修复开 Issue → 建分支 → 提 PR（写清问题、方案、前后对比、测试）→ CI 通过 → 合并。
- **CI**：GitHub Actions（公开仓库免费），跑 Ruff、后端测试（带 Postgres 服务）、网页类型检查、ESLint 和模块测试。
- **Issue 和 Milestone**：路线图拆成 Issue（读简历证据链、邮箱日历、云端子集…），比赛提交是一个 Milestone；自己用时发现的问题都记成 Issue。
- **Release**：v0.1（本机可用）、v0.2（跟进卡与竞争力）、v1.0（比赛提交），每个带 CHANGELOG。
- **节奏**：之后每周有真实的改动和一条运行报告，贡献格子自然是绿的。

### 5.4 Star：只走真实渠道

- **不买**。GitHub 可接受使用政策禁止虚假互动，违规可能删内容、封号；买来的星大多来自空号，点开 stargazers 一眼就能看出来，被面试官看到是减分。
- 北极星的目标用户就是找实习的学生，这是真实获星的机会：
  - 发一篇“我做了一个帮自己找实习的 Agent，开源了”到掘金、知乎、V2EX、牛客、小红书、即刻，附演示链接；
  - 投稿 HelloGitHub 月刊；向相关 awesome 列表提 PR；
  - 比赛 Devpost 页面、LinkedIn 和脉脉动态、B站视频都放仓库链接。
- 200–300 是努力目标，不承诺。

### 5.5 个人主页

- Profile README：一句话介绍、正在找什么实习、置顶北极星和另外 1–2 个项目、技术栈、联系方式。
- 置顶仓库只放最能代表水平的 2–3 个。

## 6. “真实生产验证”怎么让人看到

- **运行报告**（每周一份，脱敏）：采集量、从采到到可检索的时间、跟进卡发现的变化数、模型调用成本、故障和恢复；只有数字，不含原文和个人信息。放在仓库 `docs/ops/` 和项目主页。
- **工程案例**（4 个已有真实素材）：后过滤丢召回（1→32）、工具结果预算（一页 1→8 个岗位）、网络隧道直连（103 秒→2 秒）、编排层证据门禁（编造面经题→从真实帖子取证）。每个写成“现象 → 数据 → 原因 → 改法 → 前后对比 → 对应提交”。
- **评测**：一页当前版本的评测汇总；网页里的“追踪”“评测”页本身就是可观测性的展示。

## 8. 风险和对策

| 风险 | 对策 |
|---|---|
| 学生券不能用于香港地域 | 改腾讯云香港（约 199 元/年）；不走大陆，避免备案赶不上 |
| Nebius 注册、额度或接口出问题 | 尽早注册；演示实例保留百炼备用开关，但提交版本必须真实调用 Token Factory |
| 公开后泄露隐私 | 全历史扫描 + 人工审；真实数据永远不进仓库和演示 |
| 演示链接被刷，模型费用上涨 | 只读口令、每日调用上限、速率限制 |
| 比赛页有 Cloudflare 人机验证，我不能代为通过 | 规则核对和最终提交由作者本人在浏览器完成 |
| 时间不够 | 优先级：仓库公开 + CI > 演示上线 + Token Factory > 视频 > 项目主页 > 推广 |

## 9. 要作者决定和亲自做的

1. 仓库放在哪个 GitHub 账号（真名、头像完整的那个）。
2. 阿里云学生认证、买服务器、实名；是否买域名。
3. Nebius 注册，把 Token Factory 的 key 填进演示配置（密钥由作者自己填）。
4. 视频要不要出镜或配音。
5. 推广帖用作者自己的账号发。

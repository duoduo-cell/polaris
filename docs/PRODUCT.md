# 北极星：产品说明

> 2026-10-11：项目介绍、对标产品（Meta Muse、OpenAI Dots）、每日流程和核心技术点见 `INTRO.md`。本文件保留功能清单（P0、P1、P2）；数据源以 `PLAN.md` 第 4 节为准（小红书和 Boss 为核心，只看风向标大厂，不用 Tavily 和外企招聘系统）；"Hermes 做外壳"等技术说法以 `STACK.md` 和 `PLAN.md` 为准。

## 1. 定位

北极星是一个常驻云端的求职个人 agent，形态参考 OpenAI Dots 和 Meta Muse。用户不用开着手机，它自己在云端收集岗位情报，在日常聊天里更新对用户的了解，判断哪些信息值得告诉用户，并跟进每一次投递。用户先在网页里和它对话、收简报，上线后再加微信。

目标用户：不在科技中心城市、信息渠道少的求职者。

这个项目同时是作者自己的求职证明材料，要求每一项都能被 HR 点开核实。证据清单见 `PLAN.md` 第 10 节。

## 2. 运行方式

1. agent 常驻云端，自己调用工具去预设的信息源收集信息。
2. 用户在日常聊天里随口更新近况，agent 据此更新记忆。
3. agent 维护一张关于用户的"求职卡片"。
4. 新信息进来时，agent 判断是否符合用户需求、值不值得推送。
5. 记忆、检索、图谱、工具、评测配合完成整件事。

## 3. 一张卡片，三个环路

- **求职卡片**：目标岗位和开发方向、技能、经历、是否看重转正、薪资预期、偏好、短板、每家公司的进度。不要求用户事先给目标公司名单，也不要求先填自己的可实习时间；聊天里提到了再记进卡片。
- **情报环路**：采集、抽取、对齐、匹配、推送。
- **材料环路**：检查用户的仓库和 README，帮他把证明材料做完整。
- **跟进环路**：每次投递是一个状态机，到期起草跟进消息，拒绝理由回写卡片。

## 4. 数据源

| 来源 | 内容 | 档 | 接入方式 |
|---|---|---|---|
| 国内大厂招聘官网 | 新增和变更的岗位 | A | 逐家适配：直接调页面背后的接口，调不通的用浏览器 |
| 外企招聘系统 | 外企的岗位 | A | Greenhouse、Lever、Ashby 的公开接口 |
| Tavily 搜索 | 行业动向，补充发现岗位 | A | 官方 API |
| 用户主动提供 | 转发的帖子、截图、邮件、一句话备注 | A | 对话或网页粘贴 |
| GitHub | 用户自己的仓库 | A | 官方 API |
| 小红书 | 实习、内推、面经相关的笔记，从业者的经验帖 | B，必做 | xiaohongshu-mcp，本人账号 |
| Boss直聘 | 岗位列表和职位详情 | B，必做 | boss-cli，本人账号 |
| 牛客 | 实习岗位、按公司的面经 | B，有余力再做 | 浏览器自动化，不登录 |
| LinkedIn 岗位 | 外企岗位 | B，有余力再做 | JobSpy，不登录，只读公开岗位页 |
| 脉脉、LinkedIn 上的人 | 校友、内推人、HR | C | 不采集。用户自己找人和发消息，把主页或回复粘回来 |

每个数据源做成独立的、可单独开关的模块。

A 档在云端跑，进公开演示。B 档在用户自己的电脑上跑，只读、低频，结果推到云端，不进公开演示和提交材料，只在用户电脑开着时更新。C 档由 agent 起草话术、记录约聊、提醒跟进。分档的原因和规矩见 `PLAN.md` 第 4 节。

## 5. 功能

**P0**

| 功能 | 说明 |
|---|---|
| 求职卡片和对话式记忆更新 | 从聊天里抽取事实，区分新增、更新、冲突，保留历史 |
| 情报采集和发现 | 定时从各数据源采集。按方向找岗位，不按公司名单：模型扩展查询词，搜索型来源直接搜，官网型来源整批拉取，再从结果里发现新说法、新公司、新招聘入口。做法见 `PLAN.md` 第 4.1 节 |
| 结构化抽取：岗位 | 公司、岗位名称、开发方向、JD 原文和要求要点、城市、薪资、能否转正、来源链接，以及岗位自己的时间：发布时间、首次发现时间、最近一次看到、投递截止日、最早到岗时间、实习时长、每周天数。抽不到的留空 |
| 结构化抽取：经验帖 | 来自小红书和牛客的从业者经验：公司、岗位、面试轮次和题目、作者给的建议、发布时间、来源链接。挂到对应的公司和岗位上 |
| 多来源对齐和冲突处理 | 判断是否同一岗位，信息矛盾时裁决并保留出处 |
| 匹配和主动推送 | 按 JD 正文的语义算和卡片的匹配度，不看标题里有没有关键词，这样冷门方向的岗位也能找到。给出匹配理由，判断是否推送，每天一份简报和"今日一件事" |
| 近 7 天新增汇总 | 按首次发现时间算。先按方向归类，方向下面列公司，大厂单独一栏。第一次采集得到的存量标成基线，不算新增 |
| 投递管理和跟进 | 状态机，超期起草跟进消息，自动带上可提前实习的说明和作品链接，确认后由用户发出 |
| 带出处的问答 | 随时追问，回答附来源 |
| 评测和追踪页 | 各环节指标、成本、延迟、可回放的运行记录 |
| 演示模式 | 用合成数据，无需登录任何平台；提供只读演示账号，和作者自用的实例分开 |

**P1**

| 功能 | 说明 |
|---|---|
| README 教练 | 检查运行说明、架构图、接口、影响力是否齐全，在沙箱里试跑启动步骤 |
| 拒信回流和差距分析 | 拒绝理由归类，更新卡片里的短板 |
| 询问缺失信息 | 对缺失字段起草消息询问 HR，确认后发送，回复回填 |
| 日程 | 截止日、面试、实习区间写入日历并检测冲突 |
| 漏斗看板 | 各渠道投递量、回复率、面试转化 |
| 约聊记录 | 记录每次找校友和内推人的约聊，起草话术，到期提醒跟进，统计每天约聊数 |

**P2**

人脉图谱、定向自荐邮件（逐封确认后由用户发出）、作品集多版本导出、微调小模型做抽取。

**不做**

- 自动群发消息、自动打招呼、自动投递。所有对外动作由用户确认后自己发出。
- 买 star 或任何刷数据的做法。理由见 `PLAN.md` 第 10 节。

## 6. 需求来源

功能来自一份求职教练的操作清单，归成三层：

| 层 | 清单里的要求 | 对应功能 |
|---|---|---|
| 证明材料 | 作品可直接访问；项目上 GitHub；README 写清运行方式、架构图、接口、影响力；作品集 PDF | 材料环路、README 教练、作品集导出 |
| 主动触达 | 外企和大厂同时投；找校友约聊求内推；说明可提前实习；邮件自荐 | 情报环路、约聊记录、人脉图谱、定向自荐 |
| 数量和跟进 | 持续大量投递；每次投完跟进并附作品链接 | 投递管理和跟进、漏斗看板 |

# 字节跳动 Agent 方向实习岗位调研

2026-10-11。目的：技术栈选型要对得上真实 LLM 和 Agent 岗位的要求（见 `PURPOSE.md`），先看用户最想去的字节跳动在招什么样的人。

## 方法

- 来源：字节跳动校园招聘官网 jobs.bytedance.com，只用公开页面，不登录。
- 筛选：关键词 Agent，招聘项目"日常实习"，职位类别"研发"。共 **262 个**岗位，取官网默认排序的第一页 **50 个**，逐个打开详情页读"职位描述"和"职位要求"。
- 统计：每个技术点用一组关键词匹配，一个岗位提到多次只算一次。分"整段（职责加要求）"和"只在要求里"两种口径。
- 原文只留在本机，不进仓库；下面只有统计、几句短引用和岗位链接。

局限：只有一家公司；只取了第一页；关键词匹配会漏掉换了说法的同义表述。

## 岗位构成

后端和研发 24、算法和研究 13、全栈 6、数据 4、安全 2、前端 1。城市集中在北京、上海、深圳、杭州。写了到岗要求的，几乎都是"每周至少 4 天"，实习期 3 到 6 个月。

## 看出来的几件事

1. **看重的是 Agent 工程能力本身，不是框架名字。** 工具调用、评测、多 Agent、编排、RAG、规划、记忆、Harness、上下文管理都在 30% 以上；具体框架里最多的 LangChain 也只有 20%，LangGraph 6%，另有 24% 只写"熟悉主流 Agent 框架"。
2. **评测和 Trace 是硬需求。** 评测出现在 56% 的岗位里。有的岗位要做"Trace 回放、负面案例归因、成本与时延统计"（Agent 基础系统研发 - Data AML），有的要"结合 Trace/Metric/Log 与任务回放定位工具调用失败"，加分项写了 OpenTelemetry（Agent 开发 - 火山方舟），有的要分析 TTFT、吞吐、延迟、成本并做模型路由（Agent Harness 方向 - 剪映）。这和北极星"每次模型调用都记账、可回放"的设计正好对上。
3. **"Agent Harness"是热词**（32%）：运行时、多轮对话、任务编排、工具调用、上下文管理、异常恢复、可观测。宗旨里"偏评测和 harness"的方向是对的。
4. **Hermes Agent 在字节的岗位要求里被点名。** 豆包大模型 Agent Harness 算法实习生要求"了解流行的各类 Agent 应用的原理和实现细节，如 OpenClaw、HermesAgent、Codex、ClaudeCode、Managed-Agents"。比赛推荐的 Hermes 不是冷门选择。
5. **AI Coding 工具写进了 30% 岗位的要求**（"熟练使用 AI Coding 工具"）。用 Claude Code 协作开发北极星、提交记录里带协作署名，本身就是一条能核实的证据。
6. **个人项目和 Hackathon 被直接点名为加分项**（40%）。有岗位原话写着"有开源项目贡献、Hackathon 获奖、个人 Agent 项目等经历"优先。
7. **存储和检索在这些岗位里的说法是"RAG、知识库、记忆、上下文"**：RAG 42%、记忆 36%、上下文管理 30%、知识库 22%。向量数据库、Embedding、重排、知识图谱这些具体技术几乎没人写（各 0 到 1 个岗位）。所以存储和检索要做深，但对外的说法要落在"Agent 的记忆系统、上下文工程、RAG 效果评测"上。
8. **"冲突"这个词只出现 1 次**（多智能体间的冲突解决）。相关的说法是"事实性与幻觉治理""Verification"。冲突处理要做深，对外的说法是"记忆的更新和冲突消解""多源信息的事实一致性和出处追溯"。
9. **语言：Python 为主，Go 很重要**（46%，字节后端常用）。前端或全栈岗点名 TypeScript、React/Vue、Next.js、Vercel AI SDK、SSE 流式。
10. **字节官网自己已经有一个"AI 求职搭子"**（推荐岗位、查投递进度、答疑）。北极星和它的区别要说清楚：跨公司、数据归用户自己、有长期记忆、管跟进。

## 采集上的发现（给 M2）

- 官网的列表接口和详情接口都带页面自己算出的签名参数，直接调接口不行；用浏览器正常加载页面是可以的。
- 列表页接口的返回里本来就有每个岗位完整的职责和要求，所以字节官网采集器用浏览器加载列表页、读取接口返回就够了，不用逐个打开详情页。

## 1 分钟讲法

北极星是我给自己做的求职 agent：常驻采集小红书、脉脉、Boss 和三家大厂官网的岗位和面经，多来源对齐去重、冲突裁决后，进关键词 + 向量 + 知识图谱的混合检索；对话的主 agent 先过记忆（双时间线，改口要确认），再调 13 个工具查岗位、面经、图谱，必要时打开原链接或去平台现搜，回答里每个岗位和面经都能点开看原始来源。
我的技术侧重点是可靠工具调用与任务编排：保持用户条件，依据查询结果决定补查或停止，每一步留下可核实的记录。真实运行发现过放宽日期、重复检索、把更新当发布等问题，已有部分修复，但当前真实任务仍未整体通过。后续用固定条件的前后对照证明收益；旧模块分数仅用于说明各自历史实验。

## 3 分钟讲法（按面试官最常追问的顺序）

1. **为什么做、为什么是 agent 不是 workflow**：信息散在多个平台、同一岗位多处挂牌说法不一，用户的条件会变；要"查什么、查几次、要不要去原链接核对"由模型按问题决定，所以主流程是 agent；但采集、抽取、对齐、主动推送这些确定的环节是 workflow，不交给模型。
2. **数据和检索**：五个来源，按方向采；对齐用同源 JD 3-gram 相似度和跨源 SimHash，加部门层级相容和区分词，完全链接聚类；冲突字段按来源可信度和时间裁决并保留其他说法。检索三路召回，加权 RRF 融合后 qwen3-rerank 重排、MMR 去重；消融里 NDCG@10 从 BM25 的 0.73 到三路 0.81、加重排 0.89（`eval/reports/M4.md`）。
3. **记忆**：模型只抽候选事实，新增、更新、作废、追问由规则决定（同一句话两次跑出不同记忆是不能接受的）；每条事实有"什么时候成立"和"什么时候知道"两条时间线，能回答"我上个月说的是几天"；用户改口没说清时先问以哪个为准。记忆评测开发集 26/28、留出集 14/16、测试集 13/16（`eval/reports/M5.md`）。
4. **工具调用和上下文**：参数校验失败时把"哪里错、怎么改、正确示例"返回给模型；故障注入下能重试恢复；同一次回答里一模一样的查询直接复用、每种工具设上限、最后一次模型调用不给工具逼它收尾；上下文先清前几轮的工具结果（不调模型），超过 4.8 万 token 才压成摘要。
5. **评测和排错**：讲 `docs/design/DEPTH.md` 的表：四轮真实问答探针，每轮看到的失败类别、改了什么、前后数字；以及 `eval/reports/answers.md`。
6. **安全和边界**：外部原文加不可信标记，注入评测 15 次攻击 0 次被骗；删记忆要人工批准；投递、发消息只起草不代发；现查用的是我本人登录的浏览器，只读、低频、和常驻采集共用额度和锁。

## 简历条目（可直接改写，数字都能核实）

- 独立设计并实现求职个人 agent「北极星」（Python、LangGraph、PostgreSQL + pgvector + ParadeDB BM25、Neo4j、FastAPI、Next.js），覆盖采集、抽取、多源对齐、混合检索、记忆、主动推送和网页端。
- 混合检索：BM25（中文分词）+ 向量 + 知识图谱三路召回，加权 RRF + 重排 + MMR，32 题检索评测 NDCG@10 由单路 0.73 提升到 0.89。
- 多来源岗位对齐与冲突裁决：同岗识别测试集（规则冻结后标注、只评不调）F1 0.93；冲突字段保留全部来源说法。
- 双时间线记忆：模型抽候选、规则做决定，支持改口确认、历史回溯和删除；记忆评测三份标注集整句全对 26/28、14/16、13/16。
- 回答质量评测：开发集 24 题 + 留出集 14 题（正常、边界、对抗），规则检查（工具使用、编造来源、虚假声称、人工批准）+ 另一家模型按依据、深度、具体、诚实四项打分；最终版开发集 24/24、留出集 13/14、编造来源 0，单题最多工具调用 27 → 14 次；用留出集发现并撤回一版让诚实分下降的提示词。
- 可观测性与可靠性：每次模型和工具调用记录 token、耗时和错误类型，网页追踪页汇总延迟分位数和失败分类；重复调用复用、调用上限和收尾保护；提示注入评测 15 次攻击 0 次得逞。

（数字以 `eval/reports/answers.md`、`answers_v2.md` 最新一次为准；同一版本重跑会差一两题，写区间更稳：开发集 23–24/24。）

## 高频追问和答法（每条都能指到代码）

| 追问 | 答法要点 | 指给面试官看 |
|---|---|---|
| 你的 agent 循环是怎么写的？为什么用 LangGraph？ | create_agent + 中间件：重试、调用上限、摘要、上下文清理、最后一次收尾、人工审批；检查点存 Postgres，可中断恢复 | `src/polaris/agent/main.py` 的 `build` |
| 工具参数错了、调用不存在的工具怎么办？ | 运行时统一校验，错误信息写成"怎么改"返回给模型；不存在的工具不在白名单里 | `src/polaris/tools/runtime.py`、`tools/base.py` |
| 死循环、重复调用怎么防？ | 一模一样的查询复用上次结果；每种工具每次回答最多 8 到 10 次；模型调用上限 12 次，最后一次不给工具 | `runtime.py` 的 `PER_ANSWER_CAPS`、`main.py` 的 `LastCallAnswers` |
| 上下文爆了怎么办？压缩怎么不丢信息？ | 两层：先清前几轮工具结果（工具结果大、可重查），再按 token 压成摘要；用户条件不靠摘要，记在记忆卡片里常驻系统提示；探针里聊 10 轮后还能答对最早说的偏好 | `main.py` 的 `ClearEarlierTurns`、`SUMMARY_PROMPT` |
| 记忆冲突怎么处理？ | 规则表决定：同槽位新值没有改口词就先问；改口带时间就排到将来；被否认的推断按公司抑制 | `src/polaris/memory/update.py`、`docs/design/M5.md` |
| 你怎么评测 agent？ | 分层：模块指标（抽取、对齐、检索、记忆）+ 工具调用套件 + 回答质量（规则 + 异家模型打分）+ 注入；开发、留出、测试分开 | `eval/reports/` |
| 用 LLM 打分可靠吗？ | 只让它打主观项，能用规则判的都用规则（编号有没有出处由规则逐个核对，打分模型只看数字和说法）；打分模型和回答模型不同家；生成和打分分开，换了打分方式就把所有轮次只重新打分（`--rejudge`），前后用同一把尺子；标注集小、标注人就是开发者，这是已知局限 | `src/polaris/eval/answer_eval.py` 的 `rejudge` |
| 评测器自己错了怎么办？ | 第一轮 3 个失败里 2 个是评测器的错：统计结果里的编号不认（顺带发现线上同样点不开，一起修了）、拒绝时引号里的转述被当成"声称查过"；打分模型只看到截断的工具返回，把查得到的编号判成编造。每次失败先分清是模型、工具还是评测器的问题 | `docs/design/DEPTH.md` 第四轮 |
| 怎么防止在评测集上过拟合？ | 开发集 24 题拿来改；留出集 14 题在第一轮修完后、跑之前写好，之后不改题、不按它调。真抓到过一次：有一版提示词在开发集上把单题最多工具调用从 24 降到 16，留出集上反而从 12 升到 20，改掉了。同一版本跑两次看波动，小于波动的差别不算改进 | `eval/gold/answers_v2.json`、`eval/reports/answers_v2.md` |
| 调提示词有用吗？ | 早期有用（把查本地库说成现搜、说没法记这类误导，一条规则就没了）；后面几版的质量分变化都在同版本重跑的波动之内，还有一版（要求每个回答都落到用户身上、给具体下一步）深度没涨、诚实分掉了、开始编编号，撤回了。稳定的改进来自确定性改动：给工具加缺的参数（按每周天数筛）、运行时刹车（重复查询复用、每种工具上限、查满 10 次提醒收尾） | `docs/design/DEPTH.md` 第四轮的对比表 |
| 线上变慢怎么定位？ | 看追踪：每次模型调用的耗时和 token、工具耗时；之前发现过每轮都在压缩上下文导致变慢 | 网页「追踪」页 |
| 遇到过最难的 bug？ | 新库第一句话卡死：LangGraph 检查点首次建索引用 CREATE INDEX CONCURRENTLY，它要等所有事务结束，而它恰好发生在登记会话的事务里，自己等自己，后续请求占满连接池；用 py-spy 和 pg_stat_activity 定位，改成进程启动时在事务外先建好，加了能复现死锁的回归测试 | `main.py` 的 `ready`、`tests/test_live_progress.py` |
| 数据从哪来？合规吗？ | 公开官网 + 本人账号只读低频采集；不伪装、不换号、不绕验证码，被限就停；平台原文只在本机 | `docs/DATASET.md` 第 4 节 |

## 别说的话

- 别说"完全自主"：改数据要批准，对外动作只起草。
- 别说"效果很好"：说具体数字和还没解决的（标注集小、测试集记忆 13/16、模型偶尔仍会多调工具、偶尔编题号）。
- 别把某一次 24/24 当成绩：同一版本重跑会差一两题，报区间和留出集。
- 别把面经里别人的项目经历说成自己的。

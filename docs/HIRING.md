# 大厂看 Agent 实习生什么，北极星怎么证明

2026-10-12。用户要求：别闭门造车，弄清大厂面试官和 HR 最看重什么，把项目往这些点上加工。这份文件先给依据，再逐条对应北极星里能被点开核实的证据，最后写这一轮补上的东西。

## 一、依据

**我们自己采到的数据**（北极星的库，近半年，见 `eval/reports/market.md`）：

- 352 个大厂 Agent / 大模型岗位的要求：除 Python（58%）外，写得最多的是**评测/Benchmark（49%）**，其后是 Prompt（30%）、规划（25%）、RAG（25%）、工具调用（23%）、记忆（17%）、多 Agent（16%）、Harness/沙箱（13%）、上下文工程（12%）、可观测（9%）。
- 902 道亲历面经题（字节 424、阿里 112、百度 45、快手 38……）按主题：**项目深挖/落地 121** 最多，其后 RAG 87、工具调用/MCP 64、评测/指标 57、Agent 架构 51、记忆/上下文 47、多 Agent 34、安全/幻觉 19。
- 其中 170 道项目深挖和场景题在追问什么：**"为什么这么选"25**、上线与规模 21、评测与指标 14、上下文与记忆 12、数据 10、工具调用 8、失败与兜底 8、难点与踩坑 6、性能成本 6。

**外部资料**（面经汇总、横评和招聘方文章，都是第三方整理，不是官方标准）：

- 2026 年的 Agent 面试更看重工程落地、问题排查和架构设计，不靠背概念；工具调用常追问参数出错、调用不存在的工具、死循环怎么办；上下文追问压缩时怎么不丢信息；评测是 2026 年新增的重点（评测集怎么建、分层打分、发布门禁）。见 [卡码笔记的高频题汇总](https://notes.kamacoder.com/interview/llm/agent_interview.html)、[agent-interview-hub](https://github.com/Zchary1106/agent-interview-hub)。
- 字节偏底层原理和工程细节（例如三次工具调用后进入循环怎么处理：限次、检测循环、重试 → 降级 → 交给人），腾讯偏协议和概念区别、记忆设计，阿里偏架构和落地障碍（可观测性）。见 [字节/腾讯/阿里 Agent 岗面试横评](http://www.faxai.cn/archives/6508)。
- 招聘方看的是：问题拆解、可控性（权限、人工审批、回滚）、**评测纪律（正常、边界、对抗用例，错误分类，记下的失败）**、生产意识（延迟、成本、可观测、安全）、**失败分析（说得出发现了哪几类失败、改了什么）**、讲得清取舍。红旗：只展示最好的一次、说"完全自主"、堆工具名没有运行证据。见 [Provn：CPTO 怎么考 agentic 工程师](https://provn.co/blog/2026/06/agentic-engineer-hiring-requirements)、[5 AI Portfolio Projects That Actually Get You Hired](https://dev.to/klement_gunndu/5-ai-portfolio-projects-that-actually-get-you-hired-in-2026-5bpl)。
- 简历写法：每个项目写背景、职责、方案、**量化效果**、踩过的坑；准备 1 分钟和 3 分钟两个版本；每个选型都要能答"为什么不选别的"。

## 二、归纳成十个点，以及北极星的证据

| 面试官看什么 | 北极星里有什么 | 数字 | 去哪看 |
|---|---|---|---|
| 1. 讲得清"为什么这么选" | 每个模块的设计文档都写了对比和取舍：检索三路 + 重排的消融、同岗识别规则的迭代、记忆为什么"模型只抽候选、规则做决定"、为什么不换更强的模型 | 检索消融 7 种配置；模型对比 4 个 | `docs/design/`、`eval/reports/M4.md`、`docs/design/DEPTH.md` |
| 2. 评测：有评测集、有数字、分开发和留出 | 各模块都有标注集和报告，开发集、留出集、测试集分开，测试集只评不调；回答质量评测按正常、边界、对抗出题，规则检查 + 另一家模型打分，同一版本跑两次看波动 | 回答质量：开发集 24/24、23/24，留出集 13/14，编造来源 0 | `eval/reports/answers*.md`、`docs/design/DEPTH.md` 第四轮 |
| 3. 可观测性 | 每次模型和工具调用都写进库（token、耗时、出错类型）；每次回答带一条时间线；追踪页汇总延迟分位数、每次回答的调用次数、缓存命中、工具失败分类 | 追踪页实时统计 | 网页「追踪」、对话里点开「思考了 N 秒 → 查看追踪」 |
| 4. 工具调用可靠 | 参数校验并把"怎么改"返回给模型；故障注入（限流、超时）下的恢复；同一次回答里重复查询复用、每种工具设上限、最后一次调用不给工具逼它收尾；模型服务连不上时照实报错 | 工具调用套件 14 题 pass^3 100%；回答评测里单题最多调用 27 → 12–14 次；见 M2、DEPTH | `src/polaris/tools/runtime.py`、`eval/reports/M2.md` |
| 5. 上下文工程与记忆 | 两层上下文管理（先清前几轮的工具结果、不调模型；超过 4.8 万 token 才压成中文摘要）；双时间线记忆（什么时候成立、什么时候知道），改口要确认、能看来历和删除 | 记忆评测开发集 26/28、留出集 14/16、测试集 13/16；探针里压缩 14 次 → 0 次 | `eval/reports/M5.md`、`docs/design/M5.md` |
| 6. RAG 全链路 | 关键词（BM25 中文分词）+ 向量 + 知识图谱三路召回，加权 RRF 融合、重排、MMR 去重 | NDCG@10：BM25 0.73 → 三路 0.81 → 加重排 0.89 | `eval/reports/M4.md` |
| 7. 失败分析 | 每轮真实问答探针都记下失败类别和改动：把查本地库说成现搜、说"没法记"、公司级进度丢失、压缩过频、撞调用上限把报错当回答、新库第一句话死锁；回答评测里分清模型、工具、评测器各自的错 | 修之前 → 修之后，见 DEPTH.md 两张表 | `docs/design/DEPTH.md` |
| 8. 落地与真实数据 | 常驻采集在本机每天跑：小红书、脉脉、Boss、三家官网；多来源对齐和冲突裁决；每天简报和主动推送 | 1,100+ 条原始数据、320 个真实岗位、427 篇帖子、902 道亲历面经题 | 网页各页、`docs/STATUS.md` |
| 9. 安全与边界 | 外部原文加不可信标记、改数据要人工批准、对外动作（发消息、投递）不做、现查不对外开放、追踪和原始数据接口要口令 | 注入评测 15 次攻击 0 次被骗、0 次外传 | `eval/reports/injection.md` |
| 10. 延迟和成本 | 记忆抽取和回答并行；流式草稿；token 和缓存命中记录在追踪里 | 探针中位 62 秒、九成 121 秒内 | 追踪页、`docs/design/DEPTH.md` |

## 三、这一轮补上的（按上表的缺口）

- **可观测性**：以前只在库里，面试官看不到。现在每次回答带时间线（模型几次、各多久、多少 token、工具成败），新增「追踪」页汇总。
- **回答质量评测**：以前只有模块级指标，"回答好不好"靠人读。现在开发集 24 题（正常、边界、对抗）+ 留出集 14 题，规则检查可复现，另一家模型（kimi-k3）按依据、深度、具体、诚实打分，`polaris metrics answers` 一条命令重跑。
- **评测纪律**（招聘方文章里反复提的"记下的失败、错误分类、不只展示最好的一次"）：第一轮 3 个失败里 2 个是评测器自己的错，分开记；生成和打分分开，换打分方式后所有轮次只重新打分；同一版本在两个库各跑一次看波动；留出集抓到过一次过拟合（某版提示词在开发集上把最多调用从 24 降到 16，留出集上反而从 12 升到 20），还抓到一版提示词让诚实分下降、已撤回。全过程见 `docs/design/DEPTH.md` 第四轮。
- **失败与兜底**：向量服务欠费时搜索退回关键词 + 图谱、不再整个报错；图谱和当前库不同步时去掉对不上的例子并提示；工具缺参数（按每周天数筛）、输出被裁掉题号这类问题，改工具而不是靠提示词劝模型。
- **安全**：早期的追踪和原始数据接口没加口令（里面有对话、记忆和帖子原文），现在要口令。
- 面试材料：`docs/INTERVIEW.md` 给出 1 分钟和 3 分钟讲法、简历条目（只写能核实的数字）、高频追问和可以指给面试官看的代码位置。

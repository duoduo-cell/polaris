# 数据集计划：近半年的大量采集

2026-10-11 定。用户要求：先大量采集、建自己的数据集；时间范围是近半年（2026-04 起）；脉脉也自动采；定好固定格式；找到不被封的办法；说清用户要提供什么。

## 0. 要点

1. **范围**：2026-04-11 到现在，之后每天持续采。来源：22 家大厂官网、牛客、小红书、Boss直聘、脉脉、GitHub 校招汇总。
2. **格式**：四张核心表——岗位、经验帖、面试题、公司和团队（第 2 节）。岗位对齐 Google 和 schema.org 的 `JobPosting` 标准，帖子对齐 `DiscussionForumPosting`。
3. **不被封**：只当"一个真实的人"——你本人的账号、你电脑上真实的浏览器、全天慢慢采、只读、一出现限流或验证就停。不伪造指纹、不换 IP、不轮换账号（第 4 节讲原理和依据）。
4. **量从哪来**：要登录的平台（小红书、Boss、脉脉）每天有上限，靠连续采攒量；公开来源（官网、牛客、GitHub）可以全量采。
5. **采集在后台一直跑，开发不停**：采集器每天定时跑到 10-29 以后；M4 起的开发照常推进，数据越攒越多。
6. **你要提供的东西**见第 6 节：两次扫码、电脑开着、确认几个上限，不需要额外账号、代理或花钱买数据。

## 2. 统一格式

### 2.1 原始层 `raw_items`（已有，补字段）

| 字段 | 说明 | 现状 |
|---|---|---|
| `source`、`external_id`、`url` | 来源、来源里的编号、链接 | 已有 |
| `raw_text`、`raw_json`、`content_hash` | 原文、来源返回的结构化数据（去掉别人的个人信息）、内容指纹 | 已有 |
| `fetched_at` | 抓取时间 | 已有 |
| `published_at` | 来源上写的发布或更新时间 | 新增 |
| `first_seen_at`、`last_seen_at` | 第一次、最后一次采到；官网岗位据此推出挂出和下架时间 | 新增 |
| `tier` | A：公开、可进公开演示；B：要登录的平台，只在本机 | 已有 |
| `fetch_method`、`collector_version` | 接口、浏览器、站点地图、公共档案；采集器版本 | 新增 |
| `simhash` | 近似重复指纹（搬运帖、多城市同一岗位） | 新增 |

### 2.2 岗位 `job_postings`（对齐 schema.org / Google JobPosting）

| 字段 | 标准里的名字 | 说明 |
|---|---|---|
| 岗位名 | `title` | 照原文，去掉编号和公司名 |
| 职位描述 | `description` | 全文在原始层 |
| 公司 | `hiringOrganization` | 归一后的公司 + 事业群或部门（如 腾讯 / CSIG） |
| 城市 | `jobLocation` | 城市列表；远程单独标 |
| 类型 | `employmentType` | 标准值 `INTERN`、`FULL_TIME`；国内多一层：日常实习、暑期实习、校招、社招（扩展字段 `x_program`） |
| 发布日期 | `datePosted` | 来源写的；没写就用第一次采到的日期并标明 |
| 截止日 | `validThrough` | 写了才填 |
| 薪资 | `baseSalary` | 最低、最高、单位（日、月、年）、币种；写了才填 |
| 来源编号 | `identifier` | — |
| 学历、经验要求 | `educationRequirements`、`experienceRequirements` | — |
| 扩展 | `x_days_per_week`、`x_duration_months`、`x_can_convert`、`x_grad_year`、`x_directions`、`x_requirements`、`x_team`、`x_big_company` | 现有抽取已有大部分 |

### 2.3 经验帖 `posts`（对齐 schema.org DiscussionForumPosting）

| 字段 | 说明 |
|---|---|
| `headline`、`datePublished`、`interactionStatistic` | 标题、发布时间、点赞、收藏、评论数 |
| `about` | 涉及的公司和团队（归一后） |
| `post_type` | 内推、招聘、面经、经验、求助、爆料、其他（脉脉职言多一类"爆料"：裁员、调薪、组织调整） |
| 面经部分 | 岗位、轮次、时间线（投递、笔试、各轮面试、结果）、结果（通过、挂、OC） |
| 内推部分 | 能否内推、内推码是否公开、截止时间 |
| `repost_of` | 搬运的是哪条 |
| **不存** | 作者昵称、头像、学校、公司职位、联系方式；评论者的任何身份信息 |

### 2.4 面试题 `interview_questions`

| 字段 | 说明 |
|---|---|
| 题目 | 一句话 |
| 公司、团队、岗位、轮次、日期 | 从所在面经继承 |
| 类别 | 项目深挖、八股（大模型、RAG、Agent、后端……）、手撕代码、场景设计、行为 |
| 出处 | 来自哪条帖子 |
| 归并 | 同一道题的不同问法归到一组（M4 用向量做） |

### 2.5 公司和团队 `orgs`

公司、事业群、部门、团队四级；每级有别名（字节、ByteDance、TikTok、抖音；Seed、豆包大模型）。现在的大厂名单是第一级。

### 2.6 出处和数据集说明

每个结构化字段记出自哪条原文、哪次模型调用、哪版提示词（已有）。每个版本导出快照：JSONL 和 Parquet，按来源和日期分区，放 `data/datasets/`（B 档不进仓库）。按 "Datasheets for Datasets" 的提纲写说明：为什么采、包含什么、怎么采、怎么清洗、能做什么、不能做什么、怎么维护。公开仓库只放 A 档部分的说明和汇总数字。

## 4. 不被封：原理、爬虫经验、我们的做法

### 4.1 平台看什么

| 信号 | 说明 | 依据 |
|---|---|---|
| 频率和总量 | 同一账号、设备、IP 在一段时间内的请求数 | OWASP 自动化威胁 OAT-011（爬取），对应弱点是"交互频率没控制"（CWE-799） |
| 设备和浏览器指纹 | 设备编号、浏览器特征、传感器数据；**伪造指纹本身就是被找的特征** | 小红书"移动端设备风控数据工程实习生"岗位职责：挖掘"指纹伪造、异常轨迹"等风险特征 |
| 行为 | 点击路径、停留时间、滑动 | 第三方文章，可信度一般 |
| 账号关联 | 同设备、同 IP 多个账号行为一致，会被一起处理 | 第三方文章，可信度一般 |
| 内容 | 批量、同质化、引流 | xiaohongshu-mcp 作者的提醒；小红书 2025 年底封号潮的公开报道 |

### 4.2 爬虫圈的经验，取什么、不取什么

| 经验 | 出处 | 取舍 |
|---|---|---|
| 能公开采的网站，**表明身份**最有效：UA 写清是谁的程序 | Scrapy 官方文档"Avoiding getting banned" | 取（官网、牛客的 HTTP 请求） |
| 请求之间至少停 2 秒 | 同上 | 取，按来源定 1 到 5 秒 |
| 用 Common Crawl 公共档案，不给目标网站增加流量 | 同上 | 取，补牛客历史（量小） |
| 连接用户自己的真实浏览器、保留登录状态，比自动化浏览器风险低；页面需要的签名让页面自己算，不做逆向 | MediaCrawler（GitHub 上广泛使用的国内多平台采集项目）的 CDP 模式说明 | 取：脉脉用你电脑上的 Edge 专用资料夹，有窗口地跑；只读页面自己加载的数据 |
| 下载媒体串行、不并发，避免给对方服务器加压 | 同上 | 取：不下载图片视频，全部串行 |
| 轮换 UA、轮换 IP（代理池、Tor）、禁用 cookie | Scrapy 文档；MediaCrawler 的代理池功能 | **不取**。在要登录的平台上，这正是"伪装成很多人"；国内有被告因伪造 device_id、UA、IP 绕过身份校验和频率限制被判刑（锦天城律所文章） |
| 多账号、"养号" | 各类教程 | **不取**。账号关联会连带你的主号 |
| 破解签名、过验证码 | 各类教程 | **不取**。越过访问控制是法律上的关键界线；验证码也只能你本人处理 |
| "补环境"：把 Boss 的反爬脚本放到 Node 里、伪造浏览器环境来生成 `__zp_stoken__` 令牌 | 用户 10-11 发来的抖音视频（标题"听说Boss直聘补环境补到头皮发麻"）等教程 | **不取**。这是在浏览器之外伪造平台的反爬令牌，正是"绕过技术措施"；而且 Boss 一改脚本就得重来。用真实浏览器时令牌由页面自己算，根本不需要补环境 |
| DrissionPage 监听数据包（Boss 教程里最常见的工具） | CSDN 教程、DrissionPage 仓库 | **思路取，工具不取**："打开页面、读页面加载的数据"就是我们的做法；但 DrissionPage 的使用条款只允许学习和非营利用途、并要求遵守 robots 协议，和本项目的 Apache-2.0 开源不合，用已经在用的 Playwright 接上真实 Edge 实现 |

### 4.3 我们的规矩

1. 每个平台只用你本人的一个账号，在你自己的电脑上、你的网络里跑。
2. 浏览器是真实的 Edge；需要登录的平台用独立的资料夹，不碰你日常用的浏览器。
3. 每天总量有上限，全天分散，间隔随机；同一时间每个平台只有一个请求。
4. 只读：不点赞、不评论、不发布、不打招呼、不发消息。
5. 已经采过的不重复采。
6. 出现限流、验证码、登录过期、"操作频繁"提示：**这一平台当天停止**，通知你，等你看过再继续。这个次数是头号指标，目标是 0。
7. 不存别人的个人信息。

## 5. 脉脉的风险（用户已确认，记在这里）

- 脉脉的 robots.txt 对通用抓取程序只放行静态资源，对 Claude 的抓取程序写明全站禁止。所以我自己的联网工具不访问脉脉；采集只通过你电脑上、你登录的浏览器进行，由你决定是否运行。
- 职言区匿名讨论具体公司和个人，最敏感。只存和公司、团队、招聘、面试有关的内容，帖子里点名个人的部分不进结构化表。
- 脉脉自己因抓取微博数据被判过不正当竞争（三重授权原则）。说明平台方重视数据权益，账号受限的可能比小红书高。用你的号，所以上限定得比小红书低，出现任何提示立即停。

## 6. 你要提供什么

| 事项 | 什么时候 | 说明 |
|---|---|---|
| 在采集浏览器里登录 Boss 和脉脉 | 有空时 | 运行 `uv run polaris browser open`，会打开一个单独资料夹的 Edge 窗口（不碰你日常的浏览器），你在里面登录 Boss直聘和脉脉（扫码或验证码，你自己操作，密码我不碰）。之后窗口保持开着，可以最小化 |

| 确认每天上限 | 现在 | 第 3 节的建议值：小红书 250 次、Boss 150 次、脉脉 150 次、牛客 5,000 页（夜里）。觉得多或少直接改 |

| 被限流时的处理 | 发生时 | 我会停下这一平台并告诉你；需要你在手机或浏览器上看一眼账号是否正常 |
| 抽查标准答案 | 有空时 | `eval/gold/jobs_v1.jsonl` 里挑 10 条看看；新来源（牛客、脉脉、Boss）各会再出 20 条请你抽查 |

**不需要**：额外账号、代理、付费数据服务、你的密码。
